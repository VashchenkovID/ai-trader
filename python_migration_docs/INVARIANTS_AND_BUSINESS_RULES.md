# Invariants And Business Rules

## Статус миграции (на 2026-02-26)

- Документ закреплен как обязательный source of truth для `v1`.
- Инварианты должны enforce-иться на уровне домена/сервисов, а не через SQL fallback.
- Избыточные legacy-переходы и частичные режимы не переносятся в clean-реализацию.

## TradingRequest

- Нельзя исполнить заявку без `APPROVED`.
- Нельзя одобрить/отклонить не `PENDING`.
- `quantity >= 1`, `price > 0`.
- TTL заявки обязателен.

## Auto-paper

- Auto-execution только в `paper`.
- Admission gates должны быть пройдены.
- Причина блокировки должна логироваться.

## Risk/Capital

- Лимит позиции относительно портфеля обязателен.
- Daily loss/trades limits обязательны.
- Для SELL нельзя продавать больше доступной позиции.

## Migration

- Только одна активная миграция одновременно.
- Прогресс шагов монотонно возрастает.
- Статус миграции терминален в `completed|failed|cancelled`.
