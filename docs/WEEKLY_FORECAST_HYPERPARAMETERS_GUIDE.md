# Руководство по настройке гиперпараметров Weekly Forecast Model

## 📋 Обзор

Модель Weekly Forecast использует архитектуру **Seq2Seq (Encoder-Decoder)** с LSTM слоями для прогнозирования цен на 7 дней вперед. Текущие гиперпараметры являются базовыми и требуют оптимизации под конкретные инструменты и рыночные условия.

---

## 🔧 Текущие гиперпараметры

### Архитектурные параметры

| Параметр | Текущее значение | Описание |
|----------|------------------|----------|
| `inputSequenceLength` | 60 дней | Длина входной последовательности (lookback window) |
| `featureSize` | 70 фичей | Количество признаков на каждый день |
| `outputDays` | 7 дней | Количество дней для прогноза |
| `encoderLSTM1.units` | 128 | Размер скрытого состояния первого LSTM слоя encoder |
| `encoderLSTM2.units` | 128 | Размер скрытого состояния второго LSTM слоя encoder |
| `decoderLSTM1.units` | 128 | Размер скрытого состояния первого LSTM слоя decoder |
| `decoderLSTM2.units` | 128 | Размер скрытого состояния второго LSTM слоя decoder |
| `dropout` | 0.2 | Вероятность отключения нейронов (регуляризация) |
| `recurrentDropout` | 0.2 | Вероятность отключения рекуррентных связей |

### Параметры обучения

| Параметр | Текущее значение | Описание |
|----------|------------------|----------|
| `learningRate` | 0.001 | Скорость обучения (hardcoded в `model.compile()`) |
| `batchSize` | 16 | Размер батча для обучения |
| `epochs` | 50 | Количество эпох обучения |
| `validationSplit` | 0.2 | Доля данных для валидации (20%) |
| `optimizer` | Adam | Оптимизатор (Adam с lr=0.001) |
| `loss` | meanSquaredError | Функция потерь |

## 📊 Детальное описание параметров

### 1. `inputSequenceLength` (60 дней)

**Что это:**
- Количество исторических дней, которые модель "видит" перед прогнозированием
- Определяет размер окна для анализа трендов и паттернов

**Влияние:**
- ✅ **Больше (90-120 дней)**: 
  - Лучше улавливает долгосрочные тренды
  - Больше контекста для сезонности
  - ⚠️ Больше памяти и времени обучения
  - ⚠️ Может "забывать" недавние изменения
  
- ✅ **Меньше (30-45 дней)**: 
  - Быстрее обучение и inference
  - Лучше реагирует на недавние изменения
  - ⚠️ Может пропускать долгосрочные паттерны

**Рекомендации:**
- Для волатильных инструментов: **45-60 дней**
- Для стабильных инструментов: **90-120 дней**
- Для криптовалют: **30-45 дней** (быстрые изменения)

**Оптимизация:**
```javascript
// Адаптивный выбор на основе волатильности
const volatility = calculateVolatility(candles);
const inputSequenceLength = volatility > 0.3 ? 45 : volatility > 0.15 ? 60 : 90;
```

---

### 2. `featureSize` (70 фичей)

**Что это:**
- Количество признаков (features) на каждый день
- Включает: OHLCV, технические индикаторы, макро-данные, новости

**Текущий состав (примерно):**
- Базовые свечи: 5 (open, high, low, close, volume)
- Технические индикаторы: ~40-50
  - RSI, MACD, Bollinger Bands
  - SMA, EMA (разные периоды)
  - Stochastic, ATR, ADX
- Макро-данные: ~10-15
- Новости (sentiment): ~5-10

**Влияние:**
- ✅ **Больше фичей (80-100)**: 
  - Больше информации для модели
  - Потенциально выше точность
  - ⚠️ Риск переобучения
  - ⚠️ Больше времени обучения
  
- ✅ **Меньше фичей (50-60)**: 
  - Быстрее обучение
  - Меньше шума
  - ⚠️ Может не хватать информации

**Рекомендации:**
- Минимум: **50 фичей** (базовые + основные индикаторы)
- Оптимально: **70-80 фичей** (текущее значение хорошо)
- Максимум: **100 фичей** (риск переобучения)

**Оптимизация:**
- Использовать feature selection (убрать коррелирующие фичи)
- Добавить важные фичи из domain knowledge
- Удалить фичи с низкой важностью

---

### 3. `outputDays` (7 дней)

**Что это:**
- Количество дней для прогноза
- Фиксировано для Weekly Forecast (7 дней = 1 неделя)

**Влияние:**
- Больше дней → сложнее прогнозировать точно
- Меньше дней → проще, но менее полезно

**Рекомендации:**
- **7 дней** - оптимально для недельных прогнозов
- Можно добавить варианты: 3, 7, 14 дней

---

### 4. Размеры LSTM слоев (128 units)

**Что это:**
- Количество нейронов в каждом LSTM слое
- Определяет "емкость" модели (сколько паттернов может запомнить)

**Текущая архитектура:**
```
Encoder:
  LSTM1: 128 units → LSTM2: 128 units
Decoder:
  LSTM1: 128 units → LSTM2: 128 units
```

**Влияние:**
- ✅ **Больше units (256-512)**: 
  - Больше "памяти" для сложных паттернов
  - Потенциально выше точность
  - ⚠️ Значительно больше параметров (риск переобучения)
  - ⚠️ Медленнее обучение и inference
  
- ✅ **Меньше units (64-96)**: 
  - Быстрее обучение
  - Меньше риск переобучения
  - ⚠️ Может не хватать "памяти"

**Рекомендации:**
- Для простых инструментов: **64-96 units**
- Для средних: **128 units** (текущее)
- Для сложных/волатильных: **256 units**
- Можно использовать разные размеры для encoder/decoder

**Оптимизация:**
```javascript
// Адаптивный выбор на основе сложности данных
const complexity = calculateDataComplexity(features);
const units = complexity > 0.7 ? 256 : complexity > 0.4 ? 128 : 64;
```

---

### 5. `learningRate` (0.001)

**Что это:**
- Скорость, с которой модель обновляет веса
- Критически важный параметр для сходимости

**Влияние:**
- ✅ **Слишком высокий (>0.01)**: 
  - Быстрая сходимость, но может "перепрыгивать" оптимум
  - Нестабильное обучение
  - Риск расходимости
  
- ✅ **Слишком низкий (<0.0001)**: 
  - Стабильное, но медленное обучение
  - Может застрять в локальных минимумах
  - Долгое время обучения

**Рекомендации:**
- Для Adam optimizer: **0.0005 - 0.002**
- Текущее **0.001** - хорошее базовое значение
- Можно использовать learning rate scheduling:
  - Начать с 0.001, уменьшать до 0.0001
  - ReduceLROnPlateau (уменьшать при отсутствии улучшений)

**Оптимизация:**
```javascript
// Learning rate scheduling
const optimizer = tf.train.adam(0.001);
// Или использовать callbacks для адаптивного LR
callbacks: {
  onEpochEnd: (epoch, logs) => {
    if (logs.val_loss > previousValLoss) {
      // Уменьшить LR
      optimizer.setLearningRate(optimizer.learningRate * 0.9);
    }
  }
}
```

---

### 6. `batchSize` (16)

**Что это:**
- Количество примеров, обрабатываемых за один шаг градиентного спуска

**Влияние:**
- ✅ **Больше batch (32-64)**: 
  - Более стабильные градиенты
  - Быстрее обучение (лучше использование GPU)
  - ⚠️ Больше памяти
  - ⚠️ Может хуже обобщаться
  
- ✅ **Меньше batch (8-16)**: 
  - Более шумные градиенты (может помочь избежать локальных минимумов)
  - Меньше памяти
  - ⚠️ Медленнее обучение

**Рекомендации:**
- Для малых данных (<1000 примеров): **8-16**
- Для средних (1000-5000): **16-32** (текущее 16 - хорошо)
- Для больших (>5000): **32-64**

**Оптимизация:**
```javascript
// Адаптивный batch size
const dataSize = sequences.length;
const batchSize = dataSize < 500 ? 8 : 
                  dataSize < 2000 ? 16 : 
                  dataSize < 5000 ? 32 : 64;
```

---

### 7. `epochs` (50)

**Что это:**
- Количество полных проходов по обучающим данным

**Влияние:**
- ✅ **Больше epochs (100-200)**: 
  - Потенциально лучшее обучение
  - ⚠️ Риск переобучения
  - ⚠️ Долгое время обучения
  
- ✅ **Меньше epochs (20-30)**: 
  - Быстрее обучение
  - ⚠️ Может недобучиться

**Рекомендации:**
- Использовать **Early Stopping** вместо фиксированного количества
- Начать с 50, остановить при отсутствии улучшений 5-10 эпох подряд
- Для больших данных: 50-100 эпох
- Для малых данных: 30-50 эпох

**Оптимизация:**
```javascript
// Early stopping callback
callbacks: {
  onEpochEnd: (epoch, logs) => {
    if (epoch > 10 && logs.val_loss > bestValLoss) {
      patienceCount++;
      if (patienceCount >= 10) {
        // Остановить обучение
        model.stopTraining = true;
      }
    }
  }
}
```

---

### 8. `dropout` и `recurrentDropout` (0.2)

**Что это:**
- Вероятность случайного отключения нейронов во время обучения
- Регуляризация для предотвращения переобучения

**Влияние:**
- ✅ **Больше dropout (0.3-0.5)**: 
  - Сильнее регуляризация
  - Меньше риск переобучения
  - ⚠️ Может недообучиться
  
- ✅ **Меньше dropout (0.1-0.2)**: 
  - Меньше регуляризация
  - Может лучше обучаться на данных
  - ⚠️ Больше риск переобучения

**Рекомендации:**
- Текущее **0.2** - хорошее базовое значение
- Для больших данных: **0.1-0.2**
- Для малых данных: **0.3-0.4**
- `recurrentDropout` обычно равен или меньше `dropout`

## 🎯 Стратегия оптимизации

### Этап 1: Ручная настройка (Grid Search)

1. **Определить приоритетные параметры:**
   - `learningRate` (самый важный)
   - `batchSize`
   - `inputSequenceLength`
   - Размеры LSTM

2. **Создать сетку значений:**
```javascript
const hyperparameterGrid = {
  learningRate: [0.0005, 0.001, 0.002],
  batchSize: [8, 16, 32],
  inputSequenceLength: [45, 60, 90],
  lstmUnits: [64, 128, 256]
};
```

3. **Обучить модели для каждой комбинации:**
   - Использовать валидационный набор
   - Сохранять метрики (loss, MAE, RMSE)
   - Выбрать лучшую комбинацию

### Этап 2: Адаптивная настройка

1. **Анализ данных:**
   - Вычислить волатильность
   - Оценить сложность паттернов
   - Определить размер данных

2. **Автоматический выбор параметров:**
```javascript
function calculateOptimalHyperparameters(data) {
  const volatility = calculateVolatility(data);
  const dataSize = data.length;
  const complexity = calculateComplexity(data);
  
  return {
    inputSequenceLength: volatility > 0.3 ? 45 : 60,
    lstmUnits: complexity > 0.7 ? 256 : 128,
    learningRate: dataSize < 500 ? 0.0005 : 0.001,
    batchSize: dataSize < 1000 ? 16 : 32,
    epochs: dataSize < 500 ? 30 : 50
  };
}
```

### Этап 3: Per-Instrument настройка

1. **Сохранять лучшие параметры для каждого инструмента:**
   - В метаданных модели
   - В отдельной таблице БД

2. **Использовать сохраненные параметры при обучении:**
```javascript
// Загрузить сохраненные параметры для FIGI
const savedParams = await getSavedHyperparameters(figi);
const params = savedParams || defaultHyperparameters;
```

## 📊 Метрики для оценки гиперпараметров

1. **Validation Loss** - основная метрика
2. **MAE (Mean Absolute Error)** - средняя абсолютная ошибка
3. **RMSE (Root Mean Squared Error)** - корень из средней квадратичной ошибки
4. **Direction Accuracy** - точность направления движения
5. **Время обучения** - для оптимизации производительности

---

## ⚠️ Важные замечания

1. **Переобучение:**
   - Всегда используйте validation split
   - Мониторьте разницу между train и validation loss
   - Используйте early stopping

2. **Вычислительные ресурсы:**
   - Большие модели требуют больше памяти
   - Длинные последовательности замедляют обучение
   - Учитывайте ограничения при оптимизации

3. **Стабильность:**
   - Некоторые комбинации могут быть нестабильными
   - Тестируйте на нескольких инструментах
   - Сохраняйте стабильные конфигурации
