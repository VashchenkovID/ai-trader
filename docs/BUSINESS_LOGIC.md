## Обзор системы

AI Trader — это система поддержки принятия решений для торговли на фондовом рынке, использующая искусственный интеллект для генерации торговых рекомендаций и создания заявок, которые пользователь подтверждает и исполняет вручную.

### Основные возможности:

- **Генерация торговых рекомендаций** через ансамбль AI-моделей
- **Создание торговых заявок (TradingRequest)** на основе рекомендаций AI
- **Подтверждение заявок пользователем** перед исполнением
- **Ручное исполнение заявок** пользователем через брокера
- **Управление рисками** с контролем размера позиций, просадок и стоп-лоссов
- **Синхронизация портфеля** с брокером после исполнения заявок
- **Обучение моделей** на исторических данных с автоматическим обновлением
- **Аналитика и мониторинг** производительности моделей и портфеля

### Важно:

Система **НЕ исполняет сделки автоматически**. Она создает торговые заявки, которые пользователь должен:
1. Просмотреть и проанализировать
2. Подтвердить (approve) или отклонить (reject)
3. Исполнить вручную через брокера (для реальной торговли)
4. Отметить как исполненную после выполнения сделки

## Архитектура бизнес-логики

### Основные компоненты:

1. **IntegratedAIService** — центральный сервис, объединяющий все AI-модели
2. **TradingEngine** — торговый движок для исполнения ордеров
3. **RiskManagementService** — управление рисками и валидация сделок
4. **PortfolioSyncService** — синхронизация портфеля с брокером
5. **PnLCalculationService** — расчет прибыли и убытков
6. **SchedulerService** — планировщик задач (обучение, обновление данных)

### Поток данных:

```
Рыночные данные → AI-модели → Рекомендации → Валидация рисков → Создание заявки (TradingRequest) → 
Подтверждение пользователем → Ручное исполнение пользователем → Синхронизация портфеля → Расчет PnL
```

## AI-сервисы и генерация рекомендаций

### 1. IntegratedAIService

**Назначение**: Объединяет все AI-модели и генерирует финальные торговые рекомендации.

**Процесс работы**:

1. **Сбор рекомендаций от всех моделей**:
   - **EnsembleService** — ансамбль базовых моделей с разными горизонтами (краткосрочный, среднесрочный, долгосрочный)
   - **NeuralNetworkService** — традиционная нейросеть
   - **MetaLearningService** — мета-обучение для адаптации к новым условиям
   - **ReinforcementLearningService** — обучение с подкреплением
   - **StackingService** — стекинг моделей для улучшения предсказаний

2. **Взвешивание рекомендаций**:
   - Используется **ModelWeightingService** для динамического определения весов моделей
   - Веса зависят от исторической производительности каждой модели
   - Учитывается confidence (уверенность) каждой модели

3. **Агрегация результатов**:
   - Взвешенное усреднение score (оценок) от всех моделей
   - Учет согласованности между моделями (agreement)
   - Анализ новостей через **NewsAnalysisService** для корректировки sentiment

4. **Генерация финальной рекомендации**:
   - **BUY**: score > 0.7 и высокая уверенность
   - **SELL**: score < 0.3 и высокая уверенность
   - **HOLD**: во всех остальных случаях

5. **Адаптивные пороги**:
   - **AdaptiveThresholdService** динамически корректирует пороги на основе рыночных условий
   - Учитывается текущий рыночный режим через **MarketRegimeService**

### 2. EnsembleService

**Назначение**: Ансамбль моделей с разными временными горизонтами.

**Процесс работы**:

1. **Создание ансамбля**:
   - Несколько базовых моделей обучаются на разных наборах данных
   - Каждая модель имеет свой временной горизонт (1 день, 1 неделя, 1 месяц)

2. **Предсказания**:
   - Каждая модель делает независимое предсказание
   - Результаты агрегируются с учетом весов моделей

3. **Горизонты прогнозирования**:
   - **Краткосрочный** (1-3 дня): для быстрых сделок
   - **Среднесрочный** (1-2 недели): для средних позиций
   - **Долгосрочный** (1 месяц+): для долгосрочных инвестиций

4. **Согласованность (agreement)**:
   - Если все модели согласны — высокая уверенность
   - Если модели расходятся — снижается уверенность

### 3. NeuralNetworkService

**Назначение**: Базовая нейросеть для предсказания движения цены.

**Процесс работы**:

1. **Подготовка данных**:
   - Сбор исторических свечей (цены, объемы)
   - Расчет технических индикаторов (RSI, MACD, Bollinger Bands, Ichimoku)
   - Нормализация данных

2. **Предсказание**:
   - Модель получает вектор признаков (features)
   - Выдает score от 0 до 1 (вероятность роста цены)
   - Учитывается дивидендная доходность

3. **Интерпретация**:
   - Генерация объяснения предсказания
   - Указание ключевых факторов, влияющих на решение

### 4. MetaLearningService

**Назначение**: Адаптация моделей к новым рыночным условиям.

**Процесс работы**:

1. **База знаний**:
   - Хранение паттернов из прошлых рыночных условий
   - Связь паттернов с результатами торговли

2. **Адаптация**:
   - Определение текущего рыночного режима
   - Поиск похожих паттернов в базе знаний
   - Быстрая адаптация модели к новым условиям

3. **Обучение**:
   - Не требует полного переобучения модели
   - Использует transfer learning для быстрой адаптации

### 5. ReinforcementLearningService

**Назначение**: Обучение стратегии торговли через взаимодействие с рынком.

**Процесс работы**:

1. **Агент**:
   - Q-learning агент с нейронной сетью
   - Выбирает действия: HOLD, BUY, SELL

2. **Состояние (State)**:
   - Текущая цена, объем, технические индикаторы
   - Состояние портфеля (cash, позиции)
   - Рыночные условия

3. **Награда (Reward)**:
   - Положительная награда за прибыльные сделки
   - Отрицательная награда за убыточные сделки
   - Учитывается риск и просадка

4. **Обучение**:
   - Агент учится на исторических данных
   - Обновляет Q-функцию для улучшения стратегии

### 6. MultiTimeframeService

**Назначение**: Анализ на разных временных интервалах.

**Процесс работы**:

1. **Сбор данных**:
   - Анализ на интервалах: H1 (час), D1 (день), W1 (неделя)

2. **Агрегация сигналов**:
   - Сигналы с разных интервалов взвешиваются
   - Долгосрочные интервалы имеют больший вес для долгосрочных позиций

3. **Определение тренда**:
   - Если все интервалы показывают один тренд — высокая уверенность
   - Если интервалы расходятся — снижается уверенность

## Создание и управление торговыми заявками

### TradingRequestService

**Назначение**: Создание торговых заявок на основе AI-рекомендаций и управление их жизненным циклом.

**Процесс создания заявки**:

1. **Получение рекомендации**:
   - Система получает рекомендацию от AI-моделей (через IntegratedAIService)
   - Рекомендация содержит: FIGI, действие (BUY/SELL), score, confidence, обоснование

2. **Валидация через риск-менеджмент**:
   - Проверка через **RiskManagementService**
   - Проверка достаточности средств в портфеле
   - Проверка лимитов риска (размер позиции, общая экспозиция, просадка)
   - Если валидация не пройдена — заявка не создается или создается с предупреждениями

3. **Расчет параметров заявки**:
   - Получение текущей цены инструмента
   - Расчет количества акций на основе размера позиции и лимитов риска
   - Расчет примерной стоимости сделки (estimatedAmount)
   - Определение приоритета заявки (LOW, NORMAL, HIGH, URGENT)

4. **Создание TradingRequest**:
   - Сохранение заявки в БД со статусом **PENDING**
   - Заявка содержит:
     - FIGI, ticker, name инструмента
     - Действие (BUY/SELL)
     - Количество акций
     - Цену на момент создания (priceAtRequest)
     - Примерную стоимость (estimatedAmount)
     - Confidence и score из рекомендации
     - Обоснование (reasoning) и объяснение AI (aiExplanation)
     - Режим торговли (paper/real)
     - Время истечения (expiresAt) — обычно 4 часа

5. **Уведомление пользователя**:
   - Отправка уведомления через Telegram (если настроено)
   - Отображение заявки в интерфейсе приложения
   - Заявка доступна для просмотра и подтверждения

### Жизненный цикл заявки (TradingRequest):

1. **PENDING** (Ожидает подтверждения):
   - Заявка создана системой
   - Ожидает решения пользователя
   - Цена обновляется периодически (каждые N минут)
   - Может истечь (EXPIRED), если не подтверждена в течение 4 часов

2. **APPROVED** (Подтверждена):
   - Пользователь подтвердил заявку
   - Заявка готова к исполнению
   - Пользователь должен исполнить заявку вручную через брокера
   - Цена продолжает обновляться

3. **EXECUTED** (Исполнена):
   - Пользователь исполнил заявку через брокера
   - Пользователь отметил заявку как исполненную
   - Сохраняются фактические данные: actualPrice, actualAmount, commission
   - Заявка используется для синхронизации портфеля

4. **REJECTED** (Отклонена):
   - Пользователь отклонил заявку
   - Сохраняется причина отклонения (rejectionReason)
   - Заявка не исполняется

5. **CANCELLED** (Отменена):
   - Заявка отменена пользователем или системой
   - Может быть отменена при изменении условий (например, истечение срока)

6. **EXPIRED** (Истекла):
   - Заявка не была подтверждена в течение срока действия (4 часа)
   - Автоматически переводится в статус EXPIRED
   - Может быть создана новая заявка при актуальности рекомендации

### TradingEngine

**Назначение**: Вспомогательный сервис для работы с портфелем и получения рыночных данных.

**Функции**:

1. **Получение портфеля**:
   - Получение виртуального портфеля (для paper trading)
   - Получение реального портфеля от брокера (для real trading)
   - Используется для валидации заявок и расчета рисков

2. **Получение текущих цен**:
   - Получение актуальных цен инструментов
   - Используется при создании заявок и обновлении цен в заявках

3. **Виртуальный портфель (Paper Trading)**:
   - Управление виртуальным портфелем для тестирования
   - Обновление после "исполнения" заявок в paper режиме
   - Расчет виртуальной прибыли/убытка

**Важно**: TradingEngine **НЕ исполняет** реальные сделки. Он только предоставляет данные для валидации и создания заявок.

### Процесс подтверждения и исполнения заявки пользователем:

1. **Просмотр заявки**:
   - Пользователь видит заявку в интерфейсе или получает уведомление (Telegram)
   - Заявка содержит:
     - Инструмент (название, тикер)
     - Действие (BUY/SELL)
     - Количество акций
     - Текущую цену (обновляется периодически)
     - Примерную стоимость сделки
     - Confidence и score от AI
     - Обоснование и объяснение AI
     - Время истечения заявки

2. **Принятие решения**:
   - Пользователь анализирует заявку
   - Может просмотреть детали рекомендации AI
   - Может проверить текущую цену и рыночные условия

3. **Подтверждение (APPROVE)**:
   - Пользователь подтверждает заявку
   - Заявка переходит в статус **APPROVED**
   - Сохраняется время подтверждения (approvedAt)
   - Пользователь может добавить комментарий (userComment)

4. **Исполнение вручную**:
   - Пользователь открывает торговый терминал брокера
   - Создает ордер с параметрами из заявки:
     - Инструмент (FIGI или тикер)
     - Действие (BUY/SELL)
     - Количество акций
     - Тип ордера (рыночный, лимитный и т.д.)
   - Отправляет ордер брокеру
   - Ожидает исполнения ордера

5. **Отметка как исполненной (EXECUTED)**:
   - После исполнения ордера пользователь отмечает заявку как исполненную
   - Вводит фактические данные:
     - Фактическая цена исполнения (actualPrice)
     - Фактическая стоимость (actualAmount)
     - Комиссия (commission)
   - Заявка переходит в статус **EXECUTED**
   - Сохраняется время исполнения (executedAt)

6. **Синхронизация портфеля**:
   - При следующей синхронизации портфеля система:
     - Находит исполненную заявку
     - Сопоставляет с изменениями в портфеле от брокера
     - Обновляет позиции в БД
     - Рассчитывает PnL

**Альтернативные сценарии**:

- **Отклонение (REJECT)**: Пользователь может отклонить заявку с указанием причины
- **Истечение (EXPIRED)**: Заявка автоматически истекает через 4 часа, если не подтверждена
- **Отмена (CANCEL)**: Пользователь может отменить подтвержденную заявку до исполнения

### Режимы работы:

- **Paper Trading**: Виртуальная торговля для тестирования стратегий (заявки также требуют подтверждения)
- **Real Trading**: Реальная торговля, заявки исполняются пользователем вручную через брокера
- **Backtesting**: Тестирование стратегий на исторических данных

## Управление рисками

### RiskManagementService

**Назначение**: Контроль рисков и валидация торговых операций.

**Основные лимиты**:

1. **Размер позиции**:
   - Максимум 5% капитала на одну позицию (paper trading)
   - Максимум 1% капитала на одну позицию (real trading)

2. **Общая экспозиция**:
   - Максимум 40% капитала в акциях (paper trading)
   - Максимум 20% капитала в акциях (real trading)

3. **Просадка (Drawdown)**:
   - Максимальная просадка: 15%
   - При достижении лимита — остановка торговли

4. **Последовательные убытки**:
   - Максимум 10 убыточных сделок подряд
   - При достижении — временная остановка торговли

5. **Дневной убыток**:
   - Максимум 10% дневного убытка
   - При достижении — остановка торговли на день

6. **Минимальная уверенность**:
   - Минимум 60% уверенности для сделки
   - Блокировка сделок с уверенностью < 40%

7. **Волатильность**:
   - Максимум 30% волатильности инструмента
   - Высоковолатильные инструменты блокируются

**Процесс валидации ордера**:

1. **Проверка размера позиции**:
   - Расчет стоимости позиции
   - Проверка, не превышает ли она лимит

2. **Проверка общей экспозиции**:
   - Расчет текущей экспозиции портфеля
   - Проверка, не превысит ли новая позиция лимит

3. **Проверка просадки**:
   - Расчет текущей просадки
   - Проверка лимита

4. **Проверка статистики**:
   - Количество последовательных убытков
   - Дневной PnL

5. **Проверка уверенности**:
   - Минимальная уверенность модели
   - Блокировка низкоуверенных сделок

6. **Формула Келли (опционально)**:
   - Расчет оптимального размера позиции на основе исторической статистики
   - Используется консервативный коэффициент (1/4 от Келли)

**Результат валидации**:

- **isValid**: true/false
- **reason**: причина отклонения (если невалидно)
- **adjustedQuantity**: скорректированное количество (если нужно уменьшить)

## Управление портфелем

### PortfolioSyncService

**Назначение**: Синхронизация портфеля с брокером после того, как пользователь исполнил заявки вручную.

**Процесс синхронизации**:

1. **Получение снимка портфеля "до"**:
   - Сохранение текущего состояния портфеля в БД
   - Запись всех позиций и их количеств

2. **Получение актуального портфеля от брокера**:
   - Запрос к брокеру через TinkoffApiService
   - Получение реальных позиций и cash после исполнения заявок пользователем

3. **Поиск изменений**:
   - Сравнение позиций "до" и "после"
   - Определение:
     - Новых позиций (появились в реальном портфеле)
     - Закрытых позиций (исчезли из реального портфеля)
     - Изменений количества (увеличилось/уменьшилось)

4. **Сопоставление с исполненными заявками**:
   - Поиск исполненных торговых заявок (TradingRequest со статусом EXECUTED)
   - Сопоставление изменений позиций с заявками:
     - Если изменение соответствует заявке — связывание позиции с заявкой
     - Если изменение не соответствует заявке — создание "несоответствия" (unmatched)

5. **Обработка несоответствий**:
   - **Unmatched Buys**: Покупки, которые не были созданы системой (пользователь купил вручную)
   - **Unmatched Sells**: Продажи, которые не были созданы системой (пользователь продал вручную)
   - **Unmatched Closed**: Закрытые позиции без соответствующих заявок
   - Эти несоответствия логируются для анализа

6. **Обновление портфеля**:
   - Обновление позиций в БД
   - Обновление cash
   - Пересчет общей стоимости портфеля
   - Создание записей о сделках (PositionExit) для закрытых позиций

### Управление позициями:

**Важно**: Все изменения позиций происходят **только после** того, как пользователь исполнил заявку вручную через брокера.

1. **Открытие позиции**:
   - Пользователь исполняет BUY заявку через брокера
   - Пользователь отмечает заявку как EXECUTED
   - При синхронизации портфеля:
     - Создается запись о позиции в БД
     - Уменьшается cash на стоимость покупки
     - Увеличивается позиция

2. **Закрытие позиции**:
   - Пользователь исполняет SELL заявку через брокера
   - Пользователь отмечает заявку как EXECUTED
   - При синхронизации портфеля:
     - Удаление или обнуление позиции
     - Увеличение cash на стоимость продажи
     - Расчет прибыли/убытка
     - Создание записи PositionExit

3. **Частичное закрытие**:
   - Пользователь продает часть позиции
   - При синхронизации:
     - Уменьшение количества позиции
     - Частичное увеличение cash
     - Расчет частичной прибыли/убытка

4. **Пирамидинг (Pyramiding)**:
   - Система может создать новую BUY заявку для увеличения прибыльной позиции
   - Пользователь подтверждает и исполняет заявку вручную
   - При синхронизации позиция увеличивается
   - Контроль через **PyramidingService** для ограничения максимального размера

## Обучение моделей

### Процесс обучения:

1. **Подготовка данных**:
   - Сбор исторических свечей (минимум 365 дней)
   - Расчет технических индикаторов
   - Создание признаков (features) для модели

2. **Разделение данных**:
   - Training set (обучающая выборка): 70-80%
   - Validation set (валидационная выборка): 10-15%
   - Test set (тестовая выборка): 10-15%

3. **Обучение моделей**:

   **NeuralNetworkService**:
   - Обучение базовой нейросети
   - Оптимизация гиперпараметров
   - Валидация на validation set

   **EnsembleService**:
   - Обучение нескольких моделей
   - Создание ансамбля с разными весами

   **MetaLearningService**:
   - Построение базы знаний паттернов
   - Обучение адаптации к новым условиям

   **ReinforcementLearningService**:
   - Обучение Q-learning агента
   - Симуляция торговли на исторических данных
   - Обновление стратегии на основе наград

4. **Валидация**:
   - Тестирование на test set
   - Расчет метрик (accuracy, precision, recall, F1-score)
   - Проверка на переобучение (overfitting)

5. **Сохранение моделей**:
   - Сохранение весов и конфигурации
   - Версионирование моделей
   - Сохранение метаданных (дата обучения, метрики)

### Планировщик обучения:

- **Ежедневное обучение**: Быстрое обучение на последних данных (30 дней)
- **Еженедельное обучение**: Полное обучение на всех данных (365+ дней)
- **Обучение Weekly Forecast**: Прогнозирование на неделю вперед

### QuickTrainingService:

**Назначение**: Быстрое обучение всех моделей для одного инструмента.

**Процесс**:
1. Базовая нейросеть (20 эпох)
2. Ансамбль моделей (20 эпох)
3. Мета-обучение (10 эпох)
4. Обучение с подкреплением (50 эпох)
5. Weekly Forecast (20 эпох)

## Режимы торговли

### TradingModeManager

**Назначение**: Управление режимами торговли (paper/real).

**Режимы**:

1. **Paper Trading (виртуальная торговля)**:
   - Торговля на виртуальном портфеле
   - Начальный капитал: 1 млн руб
   - Все сделки виртуальные
   - Используется для тестирования стратегий

2. **Real Trading (реальная торговля)**:
   - Торговля реальными деньгами через брокера
   - Более строгие лимиты риска
   - Требуется подтверждение сделок (опционально)

**Переключение режимов**:

- Переключение через API или интерфейс
- Автоматическое применение соответствующих лимитов риска
- Сохранение состояния портфеля при переключении

## Расчет прибыли и убытков (PnL)

### PnLCalculationService

**Назначение**: Расчет прибыли и убытков по портфелю и сделкам.

**Типы PnL**:

1. **Реализованный PnL (Realized PnL)**:
   - Прибыль/убыток от закрытых позиций
   - Рассчитывается как разница между ценой продажи и ценой покупки
   - Учитываются комиссии

2. **Нереализованный PnL (Unrealized PnL)**:
   - Прибыль/убыток от открытых позиций
   - Рассчитывается как разница между текущей ценой и ценой покупки
   - Изменяется в реальном времени

3. **Общий PnL**:
   - Сумма реализованного и нереализованного PnL
   - Показывает общую прибыльность портфеля

**Процесс расчета**:

1. **Для закрытых позиций**:
   - Поиск всех закрытых сделок за период
   - Расчет прибыли/убытка для каждой сделки
   - Учет комиссий и налогов

2. **Для открытых позиций**:
   - Получение текущих цен всех позиций
   - Расчет нереализованного PnL
   - Обновление в реальном времени

3. **Агрегация**:
   - Группировка по инструментам
   - Группировка по датам
   - Расчет общей статистики

**Метрики**:

- **Total PnL**: Общая прибыль/убыток
- **Win Rate**: Процент прибыльных сделок
- **Average Win**: Средняя прибыль
- **Average Loss**: Средний убыток
- **Profit Factor**: Отношение прибыли к убыткам
- **Sharpe Ratio**: Отношение доходности к риску

## Синхронизация портфеля

### PortfolioSyncService (детально)

**Процесс синхронизации реального портфеля**:

1. **Создание снимка "до"**:
   - Сохранение текущего состояния портфеля в БД
   - Запись всех позиций и их количеств

2. **Получение актуального портфеля**:
   - Запрос к брокеру через TinkoffApiService
   - Получение реальных позиций и cash

3. **Поиск изменений**:
   - Сравнение позиций "до" и "после"
   - Определение:
     - Новых позиций (появились в реальном портфеле)
     - Закрытых позиций (исчезли из реального портфеля)
     - Изменений количества (увеличилось/уменьшилось)

4. **Сопоставление с заявками**:
   - Поиск одобренных торговых заявок (TradingRequest) за последние N часов
   - Сопоставление изменений позиций с заявками:
     - Если изменение соответствует заявке — создается запись о сделке
     - Если изменение не соответствует заявке — создается "несоответствие" (unmatched)

5. **Создание записей о сделках**:
   - Для каждого изменения создается запись о сделке
   - Сохранение: FIGI, количество, цена, дата, тип (BUY/SELL)

6. **Обновление портфеля**:
   - Обновление позиций в БД
   - Обновление cash
   - Пересчет общей стоимости портфеля

**Обработка несоответствий**:

- **Unmatched Buys**: Покупки, которые не были одобрены системой
- **Unmatched Sells**: Продажи, которые не были одобрены системой
- **Unmatched Closed**: Закрытые позиции без соответствующих заявок

Эти несоответствия логируются для анализа и могут быть обработаны вручную.

## Оптимизация входов и выходов

### EntryOptimizationService

**Назначение**: Оптимизация точки входа в позицию.

**Процесс**:

1. **Анализ спреда**:
   - Расчет исторического спреда (разница между bid и ask)
   - Определение оптимального времени для входа

2. **Анализ ликвидности**:
   - Проверка объема торгов
   - Определение возможности исполнения ордера нужного размера

3. **Технический анализ**:
   - Поиск оптимальных точек входа (поддержки, сопротивления)
   - Учет текущего тренда

4. **Рекомендация**:
   - Оптимальная цена входа
   - Оптимальное время входа
   - Рекомендуемый размер позиции

### ExitOptimizationService

**Назначение**: Оптимизация точки выхода из позиции.

**Процесс**:

1. **Анализ прибыли**:
   - Расчет текущей прибыли/убытка
   - Определение целей по прибыли

2. **Управление стоп-лоссами**:
   - Динамические стоп-лоссы через **TrailingStop**
   - Адаптация стоп-лосса к движению цены

3. **Частичное закрытие**:
   - Закрытие части позиции при достижении цели
   - Удержание остатка для дальнейшего роста

4. **Рекомендация**:
   - Оптимальная цена выхода
   - Оптимальное время выхода
   - Рекомендуемый процент закрытия

### PyramidingService

**Назначение**: Увеличение позиции при движении в прибыль.

**Процесс**:

1. **Мониторинг позиции**:
   - Отслеживание прибыли открытой позиции
   - Определение момента для увеличения

2. **Правила пирамидинга**:
   - Позиция должна быть в прибыли (минимум X%)
   - Увеличение только при продолжении тренда
   - Ограничение максимального размера позиции

3. **Расчет размера добавления**:
   - Обычно 50% от первоначальной позиции
   - Учет лимитов риска

## Мониторинг и аналитика

### PerformanceAnalyzer

**Назначение**: Анализ производительности портфеля и моделей.

**Метрики портфеля**:

1. **Доходность**:
   - Общая доходность
   - Годовая доходность
   - Доходность за период

2. **Риск**:
   - Волатильность портфеля
   - Максимальная просадка (Max Drawdown)
   - Value at Risk (VaR)

3. **Сравнение с бенчмарком**:
   - Сравнение с индексом (например, MOEX)
   - Alpha (превышение доходности)
   - Beta (чувствительность к рынку)

4. **Распределение**:
   - По секторам
   - По инструментам
   - По типам активов

**Метрики моделей**:

1. **Точность предсказаний**:
   - Accuracy (точность)
   - Precision (точность положительных предсказаний)
   - Recall (полнота)
   - F1-score (гармоническое среднее)

2. **Торговая производительность**:
   - Win Rate (процент прибыльных сделок)
   - Average Win/Loss
   - Profit Factor

3. **Сравнение моделей**:
   - Сравнение производительности разных моделей
   - Определение лучшей модели для каждого инструмента

### ModelMonitoringService

**Назначение**: Мониторинг производительности моделей в реальном времени.

**Процесс**:

1. **Отслеживание предсказаний**:
   - Сохранение всех предсказаний моделей
   - Сравнение с фактическими результатами

2. **Детекция деградации**:
   - Обнаружение снижения точности моделей
   - Алерты при превышении порога ошибок

3. **Рекомендации по переобучению**:
   - Автоматическое предложение переобучения при деградации
   - Планирование переобучения

### WorkerMonitoringService

**Назначение**: Мониторинг фоновых задач (workers).

**Отслеживаемые задачи**:

- Обучение моделей
- Обновление данных
- Анализ портфеля
- Генерация прогнозов

**Метрики**:

- Прогресс выполнения
- Время выполнения
- Статус (running, completed, failed)
- Ошибки

## Заключение

Данная документация описывает основную бизнес-логику приложения AI Trader. Система представляет собой комплексное решение для поддержки принятия торговых решений, объединяющее:

- **Множественные AI-модели** для генерации рекомендаций
- **Создание торговых заявок** на основе рекомендаций с валидацией рисков
- **Подтверждение заявок пользователем** перед исполнением
- **Ручное исполнение заявок** пользователем через брокера
- **Синхронизацию портфеля** после исполнения заявок
- **Управление рисками** для защиты капитала
- **Мониторинг и аналитику** для отслеживания производительности

### Ключевые особенности:

1. **Система не исполняет сделки автоматически** — все заявки требуют подтверждения и ручного исполнения пользователем
2. **Пользователь имеет полный контроль** — может подтверждать, отклонять или изменять заявки
3. **AI предоставляет рекомендации** — система анализирует рынок и предлагает действия, но окончательное решение принимает пользователь
4. **Синхронизация после исполнения** — портфель обновляется после того, как пользователь исполнил заявку через брокера

Все компоненты работают совместно для обеспечения эффективной поддержки принятия торговых решений с сохранением контроля пользователя над исполнением сделок.
