# Отчет об обновлении цен на инструменты

## Механизмы обновления цен

В системе реализовано несколько механизмов обновления цен для разных целей:

### 1. Обновление цен всех инструментов (Price Update)

**Частота**: Каждые **60 минут** (по умолчанию)

**Настройка**: `price_update_interval_minutes` в настройках планировщика

**Расписание**: `*/${priceUpdateIntervalMinutes} * * * *` (cron)

**Описание**:
- Обновляет цены для всех активных инструментов в кеше
- Использует worker процесс (`priceUpdateWorker.js`)
- Обрабатывает инструменты батчами по 50 штук (лимит API)
- Обновляет поля `lastPrice` и `lastPriceTime` в таблице `CachedInstrument`

**Код**: `server/src/services/SchedulerService.js:174-188`

### 2. Обновление цен портфеля (Portfolio Prices Update)

**Частота**: Каждые **10 минут** (по умолчанию)

**Настройка**: `portfolio_prices_update_interval_minutes` в настройках планировщика

**Расписание**: `*/${portfolioPricesUpdateIntervalMinutes} * * * *` (cron)

**Описание**:
- Обновляет цены только для инструментов, которые есть в активных позициях портфеля
- Использует worker процесс (`portfolioPricesUpdateWorker.js`)
- Более частое обновление для актуальных данных портфеля
- Обновляет поля `lastPrice` и `lastPriceTime` в таблице `CachedInstrument`

**Код**: `server/src/services/SchedulerService.js:190-204`

### 3. Обновление цен для торговых заявок (Trading Requests Prices Update)

**Частота**: Зависит от наличия активных торговых заявок

**Описание**:
- Обновляет цены для инструментов с активными торговыми заявками
- Использует worker процесс (`tradingRequestsPricesUpdateWorker.js`)
- Проверяет условия исполнения заявок после обновления цен
- Запускается по требованию или по расписанию

**Код**: `server/src/workers/tradingRequestsPricesUpdateWorker.js`

### 4. Обновление цен для активных сигналов (Active Signals Prices Update)

**Частота**: Зависит от наличия активных сигналов

**Описание**:
- Обновляет цены для инструментов с активными торговыми сигналами
- Использует worker процесс (`activeSignalsPricesUpdateWorker.js`)
- Обеспечивает актуальные цены для принятия решений о входе в позиции

**Код**: `server/src/workers/activeSignalsPricesUpdateWorker.js`

## Настройки по умолчанию

Настройки хранятся в таблице `Settings` и инициализируются в `initDatabase.js`:

```javascript
// Обновление цен всех инструментов
{
    key: 'price_update_interval_minutes',
    value: '60', // минут
    category: 'scheduler'
}

// Обновление цен портфеля
{
    key: 'portfolio_prices_update_interval_minutes',
    value: '10', // минут
    category: 'scheduler'
}
```

## Изменение частоты обновления

Частоту обновления можно изменить через:

1. **API**: `PUT /api/settings/:key` с новым значением
2. **База данных**: Прямое изменение в таблице `Settings`
3. **Административная панель**: Через интерфейс настроек (если реализован)

После изменения настройки необходимо перезапустить `SchedulerService` для применения изменений.

## Оптимизация

### Текущие настройки оптимизированы для:
- **Низкой нагрузки на API** - обновление всех инструментов раз в час
- **Актуальности данных портфеля** - обновление портфеля каждые 10 минут
- **Эффективности** - использование worker процессов для параллельной обработки
- **Батчинг** - обработка по 50 инструментов за раз (лимит API Tinkoff)

### Рекомендации по настройке:

**Для активной торговли**:
- `price_update_interval_minutes`: 30-60 минут (баланс между актуальностью и нагрузкой)
- `portfolio_prices_update_interval_minutes`: 5-10 минут (для быстрого реагирования)

**Для долгосрочных инвестиций**:
- `price_update_interval_minutes`: 60-120 минут (снижение нагрузки)
- `portfolio_prices_update_interval_minutes`: 15-30 минут (достаточно для мониторинга)

**Для тестирования/разработки**:
- `price_update_interval_minutes`: 5-10 минут (быстрое получение данных)
- `portfolio_prices_update_interval_minutes`: 2-5 минут (максимальная актуальность)

## Мониторинг

Все обновления цен логируются и могут быть отслежены через:
- Логи worker процессов
- Мониторинг воркеров через `WorkerMonitoringService`
- Метрики в базе данных (время последнего обновления в `CachedInstrument.lastPriceTime`)

## Технические детали

### Worker процессы

Все обновления цен выполняются в отдельных worker процессах для:
- Изоляции от основного процесса
- Параллельной обработки
- Устойчивости к ошибкам

### Обработка ошибок

- При ошибке обновления одного инструмента, обработка продолжается для остальных
- Ошибки логируются, но не прерывают процесс
- Повторные попытки выполняются при следующем запуске задачи

### Производительность

- Батчинг по 50 инструментов (лимит API)
- Параллельная обработка батчей
- Кеширование результатов в `CachedInstrument`
