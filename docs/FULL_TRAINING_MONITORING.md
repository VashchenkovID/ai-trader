# Полное обучение нейросетей: Мониторинг и расписание

## Обзор

Полное обучение нейросетей теперь унифицировано и использует один и тот же код для:
- **Планового обучения** (по расписанию)
- **Ручного запуска** (кнопка на фронтенде)

## Расписание

### Настройка расписания

Расписание задается в настройках системы через параметр `nn_training_schedule` (cron формат).

**По умолчанию:** `'0 3 * * 1'` (понедельник в 3:00)

**Доступные варианты:**
- `'0 3 * * 1'` - Понедельник в 3:00 (рекомендуется, после обновления кеша в 2:00)
- `'0 3 * * *'` - Ежедневно в 3:00 (не рекомендуется из-за длительности процесса)
- `'0 2 * * 1'` - Понедельник в 2:00
- `'0 4 * * 1'` - Понедельник в 4:00
- `'0 0 * * 1'` - Понедельник в 0:00
- `'0 3 * * 0'` - Воскресенье в 3:00

### Где проверить текущее расписание

1. **В базе данных:** Таблица `settings`, ключ `nn_training_schedule`
2. **В коде:** `server/src/services/SchedulerService.js`, строка 139
3. **В настройках фронтенда:** Страница "Настройки" → "Планировщик"

## Условия запуска

Обучение может не запуститься по следующим причинам:

### 1. Проверка `shouldRetrainModel()`

**Условие:** Если модель не требует переобучения, обучение пропускается.

**Проверяется:**
- Возраст модели (по умолчанию: 7 дней)
- Деградация модели (если точность упала более чем на 5%)

**Как обойти:** Использовать параметр `force: true` при ручном запуске.

**Логирование:** 
```
ℹ️ [Full Training] Обучение не требуется по результатам проверки shouldRetrainModel
```

### 2. Полное обновление кеша

**Условие:** Если идет полное обновление кеша (`isFullCacheUpdateRunning === true`), обучение пропускается.

**Как обойти:** Дождаться завершения обновления кеша.

**Логирование:**
```
ℹ️ [Full Training] Пропущено: идет полное обновление кеша
```

### 3. Уже идет обучение или анализ

**Условие:** Если уже запущено обучение (`isTraining === true`) или анализ (`isAnalyzing === true`), новое обучение пропускается.

**Как обойти:** Использовать параметр `force: true` при ручном запуске, или дождаться завершения текущего процесса.

**Логирование:**
```
ℹ️ [Full Training] Пропущено: уже идет обучение или анализ
```

### 4. Кеш устарел

**Условие:** Если кеш устарел (`isCacheStale() === true`) и `skipIfStale: false`, обучение ждет обновления кеша.

**Настройка:** В `SchedulerUtils.createScheduledTask` для задачи обучения установлено `skipIfStale: false`, что означает ожидание обновления кеша.

## Мониторинг воркеров

### Регистрация воркера

При старте полного обучения автоматически регистрируется воркер в `WorkerMonitoringService`:

```javascript
{
  type: 'training',
  name: 'Полное обучение нейросетей',
  metadata: {
    trainingType: 'full',
    stages: ['base', 'ensemble', 'meta', 'rl'],
    currentStage: 'initializing'
  }
}
```

### Обновления прогресса

Воркер обновляет свой статус на каждом этапе:

1. **Инициализация (5-10%)**
   - Проверка деградации моделей
   - Подготовка к обучению

2. **Этап 1: Базовая нейросеть (15-40%)**
   - Для каждого инструмента:
     - `currentStage`: "Этап 1/4: Базовая нейросеть для {ticker}"
     - `stage`: "base"
     - `trainingStage`: 1
     - `currentInstrument`: номер инструмента
     - `totalInstruments`: общее количество
     - `currentTicker`: тикер инструмента
     - `figi`: FIGI инструмента

3. **Этап 2: Ансамбль (40-65%)**
   - Аналогично этапу 1, но `stage: "ensemble"`, `trainingStage: 2`

4. **Этап 3: Мета-обучение (65-90%)**
   - Аналогично, но `stage: "meta"`, `trainingStage: 3`

5. **Этап 4: Обучение с подкреплением (90-100%)**
   - Аналогично, но `stage: "rl"`, `trainingStage: 4`

### Завершение воркера

При успешном завершении:
```javascript
{
  success: true,
  totalTrained: количество_инструментов,
  successes: успешных,
  failures: ошибок,
  duration: время_в_секундах,
  durationText: "Xч Ym"
}
```

При ошибке:
```javascript
{
  success: false,
  error: сообщение_об_ошибке,
  duration: время_до_ошибки
}
```

## Telegram уведомления

### Старт обучения

**Событие:** `TRAINING_STARTED`
**Тип:** `info`

**Формат:**
```
🧠 ПОЛНОЕ ОБУЧЕНИЕ НАЧАЛОСЬ

📊 Параметры:
• Инструментов в очереди: {количество}
• Дней данных: {дней}
• Этапы: Базовая → Ансамбль → Мета-обучение → RL

⏱️ Ожидаемое время: ~{минут} минут
```

### Завершение обучения

**Событие:** `TRAINING_COMPLETED`
**Тип:** `success`

**Формат:**
```
✅ ПОЛНОЕ ОБУЧЕНИЕ ЗАВЕРШЕНО

📊 Результаты:
• Всего обработано: {количество} инструментов
• ✅ Успешно: {успешных}
• ❌ Ошибок: {ошибок}
• ⏱️ Время выполнения: {время}

🧠 Все этапы обучения завершены:
• Базовая нейросеть
• Ансамбль моделей
• Мета-обучение
• Обучение с подкреплением
```

### Ошибка обучения

**Событие:** `TRAINING_ERROR`
**Тип:** `critical`

**Формат:**
```
🚨 ОШИБКА ПОЛНОГО ОБУЧЕНИЯ

❌ {сообщение_об_ошибке}

⏱️ Время до ошибки: {секунды}с

⚠️ Обучение прервано
```

## API для ручного запуска

### Эндпоинт

`POST /api/training/batch-train-all`

### Параметры

```json
{
  "epochs": 10,        // Опционально, по умолчанию 10
  "batchSize": 32,     // Опционально, по умолчанию 32
  "force": false       // Опционально, принудительный запуск
}
```

### Ответ

**Успешный запуск:**
```json
{
  "success": true,
  "message": "Полное обучение всех нейросетей запущено",
  "data": {
    "epochs": 10,
    "batchSize": 32,
    "force": false
  }
}
```

**Уже запущено:**
```json
{
  "success": false,
  "message": "Обучение уже запущено",
  "isRunning": true
}
```

## Отслеживание на фронтенде

### WebSocket события

1. **`worker_started`** - Воркер зарегистрирован
2. **`worker_progress`** - Обновление прогресса
3. **`worker_status_update`** - Изменение статуса
4. **`batch_training_all_completed`** - Обучение завершено
5. **`batch_training_all_error`** - Ошибка обучения

### API для получения статуса

`GET /api/worker-monitoring/workers` - Список активных воркеров
`GET /api/worker-monitoring/workers/:workerId` - Детали воркера

## Диагностика проблем

### Обучение не запускается по расписанию

1. **Проверить расписание:**
   ```sql
   SELECT value FROM settings WHERE key = 'nn_training_schedule';
   ```

2. **Проверить логи:**
   - Искать сообщения `[Full Training] Пропущено:`
   - Проверить причину пропуска

3. **Проверить условия:**
   - `shouldRetrainModel()` возвращает `false`?
   - Идет обновление кеша?
   - Уже запущено обучение?

### Обучение запускается, но не видно прогресса

1. **Проверить регистрацию воркера:**
   - `GET /api/worker-monitoring/workers?type=training`
   - Должен быть активный воркер с `type: 'training'`

2. **Проверить WebSocket соединение:**
   - События `worker_progress` должны приходить

3. **Проверить логи:**
   - Должны быть сообщения об обновлении прогресса

## Рекомендации

1. **Расписание:** Рекомендуется запускать полное обучение в нерабочее время (например, в 3:00)
2. **Частота:** Не чаще одного раза в день
3. **Мониторинг:** Следить за Telegram уведомлениями о старте и завершении
4. **Принудительный запуск:** Использовать `force: true` только при необходимости, так как это может перезаписать недавно обученные модели
