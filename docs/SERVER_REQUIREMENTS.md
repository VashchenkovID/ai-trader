# Требования к серверу для AI Trader

## 📊 Анализ после оптимизаций

После всех оптимизаций, учитывая низкую нагрузку (не более 10 обращений в день), требования к серверу были значительно снижены.

---

## 💻 Минимальные требования (рекомендуемые)

### Процессор (CPU)
- **Минимум**: 2 ядра (2 vCPU)
- **Рекомендуется**: 4 ядра (4 vCPU)
- **Обоснование**: 
  - Максимум 3 одновременных воркера (`maxConcurrent = 3`)
  - Фоновые задачи выполняются редко (раз в час/день)
  - Низкая нагрузка от пользователей (≤10 раз/день)

### Оперативная память (RAM)
- **Минимум**: 2 GB
- **Рекомендуется**: 4 GB
- **Обоснование**:
  - Node.js приложение: ~500-800 MB
  - PostgreSQL: ~200-400 MB (с пулом 2-15 соединений)
  - Воркеры: ~100-200 MB каждый (макс. 3 одновременно)
  - Кеш данных: ~200-500 MB
  - Резерв для системы: ~500 MB

### Дисковое пространство
- **Минимум**: 20 GB SSD
- **Рекомендуется**: 50 GB SSD
- **Распределение**:
  - Приложение: ~2-3 GB
  - PostgreSQL БД: ~5-10 GB (зависит от объема данных)
  - Логи (ротация): ~2-5 GB
  - Модели нейросетей: ~5-10 GB
  - Резерв: ~5-10 GB

### Сеть
- **Минимум**: 10 Mbps (входящий/исходящий)
- **Рекомендуется**: 50-100 Mbps
- **Обоснование**:
  - API запросы к Tinkoff: ~1-5 Mbps
  - WebSocket соединения: минимальная нагрузка
  - Обновления данных: периодические, не критично

## 🗄️ База данных (PostgreSQL)

### Текущие настройки пула соединений
```javascript
pool: {
    max: 15,  // Максимум соединений (оптимизировано)
    min: 2,   // Минимум соединений (экономия ресурсов)
    acquire: 60000,  // 60 секунд ожидания
    idle: 300000,    // 5 минут простоя
    evict: 5000      // Проверка каждые 5 секунд
}
```

### Требования к PostgreSQL
- **Версия**: PostgreSQL 12+ (рекомендуется 14+)
- **RAM для БД**: 512 MB - 1 GB (в рамках общего RAM)
- **Диск**: SSD обязательно (для производительности)
- **Индексы**: Автоматически создаются через Sequelize

## ⚙️ Оптимизированные настройки

### Воркеры
- **Максимум одновременных**: 3 (`WorkerPriorityManager.maxConcurrent`)
- **Приоритетная очередь**: Да
- **Типы воркеров**: 
  - Критичные (100): обновление цен портфеля, заявок, сигналов
  - Обычные (50-70): обновление цен, кеша, обучение
  - Фоновые (20-30): опционы, фундаментальные данные

### API запросы
- **Rate limiting**: Token bucket (20 токенов, 10 токенов/сек)
- **Батчинг**: Да (до 50 запросов в батче)
- **Приоритетная очередь**: Да

### Кеширование
- **TTL кеша**: 24 часа (было 6 часов)
- **Ротация логов**: 20 MB файл, 14 дней (combined), 30 дней (error)

### Планировщик задач (интервалы)
- **Обновление цен**: Каждый час (было 20 минут)
- **Обновление цен портфеля**: Каждые 10 минут (было 2 минуты)
- **Обновление опционов**: Раз в 2 дня (было ежедневно)
- **Фундаментальные данные**: Раз в 2 недели (было еженедельно)
- **Обновление кеша**: Каждые 4 часа

## 📈 Пиковая нагрузка

### Сценарий максимальной нагрузки
- **Пользователи**: 1-2 одновременных сессии
- **Воркеры**: 3 активных (максимум)
- **API запросы**: ~10-20 запросов/минуту (с rate limiting)
- **БД запросы**: ~50-100 запросов/минуту (с пулом 15 соединений)

### Ресурсы при пиковой нагрузке
- **CPU**: 40-60% (4 ядра)
- **RAM**: 2.5-3.5 GB
- **Диск I/O**: Низкая (SSD справляется легко)
- **Сеть**: 5-10 Mbps

## 📊 Мониторинг ресурсов

### Ключевые метрики для отслеживания
1. **CPU**: Средняя загрузка < 50%
2. **RAM**: Использование < 80% (3.2 GB из 4 GB)
3. **Диск**: Свободное место > 20%
4. **БД соединения**: Активные < 12 из 15
5. **Воркеры**: Активные < 3

### Алерты
- CPU > 80% более 5 минут
- RAM > 90% более 5 минут
- Диск < 10% свободного места
- БД соединения > 13 из 15
- Ошибки БД > 10 в минуту

## ⚠️ Важные замечания

### 1. SSD обязательно
- HDD не подходит для PostgreSQL и Node.js
- SSD критичен для производительности БД

### 2. Резервное копирование
- Рекомендуется автоматическое резервное копирование БД
- Хранить минимум 7 дней бэкапов

### 3. Мониторинг
- Настроить мониторинг ресурсов (CPU, RAM, диск)
- Настроить алерты при превышении лимитов

### 4. Масштабирование
- При увеличении нагрузки (более 10 пользователей/день):
  - Увеличить RAM до 8 GB
  - Увеличить CPU до 4-6 ядер
  - Увеличить пул БД до 20-30 соединений
