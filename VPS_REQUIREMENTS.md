# Требования к VPS для стабильной работы приложения AI Trader

> **Примечание**: Документ составлен для использования приложения **одним пользователем** (личное использование)

## 📊 Анализ архитектуры приложения

### Компоненты системы:
- **Backend**: Node.js (Express) с множеством фоновых задач
- **Frontend**: React (Vite) - может быть собран статически
- **База данных**: PostgreSQL с пулом соединений (max: 20, min: 5)
- **WebSocket**: Real-time обновления для одного клиента
- **Worker Threads**: 12 параллельных воркеров для тяжелых операций
- **TensorFlow.js**: Обучение и инференс нейронных сетей
- **Cron задачи**: 31+ запланированных задач

---

## 💻 Минимальные требования (для тестирования)

### CPU
- **Ядра**: 2 vCPU
- **Архитектура**: x86_64
- **Производительность**: Базовые частоты 2.0+ GHz

### RAM
- **Объем**: 4 GB
- **Использование**:
  - Node.js процесс: ~400-600 MB
  - PostgreSQL: ~400-500 MB
  - TensorFlow.js (обучение): ~1-2 GB (пиковые нагрузки)
  - Worker threads: ~200-400 MB каждый (до 12 воркеров, но обычно активны 2-4)
  - WebSocket: ~10-20 MB (одно соединение)
  - Система: ~500 MB
  - **Итого**: ~3.5-5 GB в пиковые моменты

### Диск
- **SSD**: 40 GB
- **Использование**:
  - Приложение: ~2 GB
  - Node modules: ~1 GB
  - PostgreSQL данные: ~5-10 GB (начальный объем)
  - Логи: ~1-2 GB
  - Резервное копирование: ~5 GB
  - **Рост**: ~1-2 GB/месяц (свечи, сигналы, кеш)

### Сеть
- **Пропускная способность**: 100 Mbps
- **Трафик**: ~5-10 GB/месяц (API запросы, одно WebSocket соединение)

## 🚀 Рекомендуемые требования (для продакшена)

### CPU
- **Ядра**: 2-4 vCPU
- **Архитектура**: x86_64
- **Производительность**: 2.5+ GHz
- **Обоснование**:
  - Параллельная обработка воркеров (обычно 2-4 активных одновременно)
  - Обучение нейронных сетей (CPU-intensive)
  - Множество запланированных cron задач (но не все выполняются одновременно)
  - WebSocket для одного клиента (минимальная нагрузка)

### RAM
- **Объем**: 6-8 GB (рекомендуется 8 GB)
- **Детальное использование**:
  - Node.js основной процесс: ~600-800 MB
  - PostgreSQL (с пулом до 20 соединений, но обычно используется 5-10): ~800 MB - 1.5 GB
  - TensorFlow.js модели в памяти: ~300-500 MB
  - Обучение нейронных сетей: ~2-3 GB (пиковые нагрузки, обычно одно обучение)
  - Worker threads (обычно активны 2-4 из 12): ~1-2 GB суммарно
  - Кеш в памяти (Node-cache): ~100-300 MB
  - WebSocket (одно соединение): ~10-20 MB
  - Система и другие процессы: ~800 MB - 1 GB
  - **Итого**: 6-8 GB в обычной работе
  - **Пиковые нагрузки**: до 10-12 GB при обучении модели и активной работе воркеров

### Диск
- **SSD**: 60-80 GB (рекомендуется 100 GB)
- **Тип**: SSD (NVMe предпочтительно, но не обязательно)
- **Использование**:
  - Приложение: ~2-3 GB
  - Node modules: ~1-1.5 GB
  - PostgreSQL данные: ~10-30 GB (зависит от количества отслеживаемых инструментов)
    - Свечи: ~5-15 GB (365 дней × выбранные инструменты)
    - Сигналы: ~2-5 GB
    - Кеш инструментов: ~500 MB - 1 GB
    - Опционные данные: ~2-5 GB
    - Модели нейросетей: ~500 MB - 2 GB
  - Логи: ~3-5 GB (ротация)
  - Резервное копирование: ~10-15 GB
  - **Рост**: ~2-5 GB/месяц при активном использовании

### Сеть
- **Пропускная способность**: 100 Mbps (1 Gbps опционально)
- **Трафик**: ~20-40 GB/месяц
- **Обоснование**:
  - API запросы к Tinkoff API (rate-limited, но частые)
  - Одно WebSocket соединение (real-time обновления)
  - Загрузка исторических данных
  - Обновление опционных данных

- **Обоснование**:

  - PostgreSQL с оптимизированным кешированием

### Диск
- **SSD**: 150-200 GB (NVMe предпочтительно)
- **Обоснование**: 
  - Большой объем исторических данных (множество инструментов)
  - Быстрый доступ к БД (критично для производительности)
  - Резервные копии и архивы

## 🔧 Специфические требования

### PostgreSQL
- **Версия**: 12+ (рекомендуется 14+)
- **Конфигурация** (для одного пользователя):
  - `max_connections`: 50-100 (приложение использует пул до 20, но для одного пользователя достаточно 30-50)
  - `shared_buffers`: 25% от RAM (1.5-2 GB для 6-8 GB RAM)
  - `effective_cache_size`: 50-75% от RAM
  - `work_mem`: 16-32 MB (для одного пользователя достаточно)
  - `maintenance_work_mem`: 512 MB - 1 GB
  - `checkpoint_completion_target`: 0.9
  - `wal_buffers`: 16 MB
  - `default_statistics_target`: 100

### Node.js
- **Версия**: 18.0.0+ (LTS)
- **Оптимизации**:
  - `NODE_OPTIONS=--max-old-space-size=3072` (для 4-6 GB RAM)
  - `NODE_OPTIONS=--max-old-space-size=4096` (для 8 GB RAM)
  - `NODE_OPTIONS=--max-old-space-size=6144` (для 12 GB RAM)
  - Использование PM2 или systemd для управления процессом

### Системные зависимости
- **ОС**: Ubuntu 20.04+ / Debian 11+ / CentOS 8+
- **Пакеты**:
  - build-essential (для компиляции нативных модулей)
  - python3 (для некоторых npm пакетов)
  - git

## 📈 Факторы, влияющие на ресурсы

### Основные факторы нагрузки:

1. **Количество отслеживаемых инструментов**:
   - 50-100 инструментов: минимальные требования (4 GB RAM)
   - 200-300 инструментов: рекомендуемые требования (6-8 GB RAM)
   - 500+ инструментов: оптимальные требования (12-16 GB RAM)

2. **Частота обновлений и активность**:
   - Обновление цен: каждые 1-5 минут
   - Обновление кеша: каждые 6 часов
   - Обучение моделей: ежедневно/по требованию
   - Интенсивное использование всех функций увеличивает нагрузку

3. **Обучение нейронных сетей**:
   - Одно обучение: +2-3 GB RAM временно
   - Параллельное обучение нескольких моделей: +2-3 GB на каждую модель
   - Рекомендуется обучать модели последовательно для экономии ресурсов

4. **Объем исторических данных**:
   - Хранение данных за 365 дней: ~5-15 GB
   - Хранение данных за 2+ года: ~15-30 GB
   - Влияет на размер БД и время запросов

## ⚠️ Критические моменты

### Память (RAM)
- **Самое критичное требование** из-за:
  - TensorFlow.js требует много памяти для обучения
  - Множество воркеров работают параллельно
  - PostgreSQL кеширует данные в памяти
  - Недостаток RAM приведет к использованию swap, что сильно замедлит работу

### Диск (I/O)
- **SSD обязательно** для:
  - Быстрого доступа к БД (критично для производительности)
  - Записи логов
  - Операций с большими объемами данных (свечи, сигналы)

### CPU
- **Многоядерность важна** для:
  - Параллельной работы воркеров (обычно 2-4 активных одновременно)
  - Обучения нейронных сетей (может использовать несколько ядер)
  - Обработки запросов и фоновых задач одновременно

## 🔍 Мониторинг и оптимизация

### Метрики для отслеживания:
1. **RAM usage**: не должно превышать 80% постоянно (для одного пользователя обычно 50-70%)
2. **CPU usage**: средняя нагрузка < 60% (пики до 80% при обучении допустимы)
3. **Disk I/O**: wait time < 10%
4. **PostgreSQL connections**: активные соединения обычно 5-15 из 20 (для одного пользователя)
5. **Worker threads**: количество активных воркеров (обычно 2-4 из 12)

### Оптимизации:
1. Настроить PostgreSQL под доступные ресурсы
2. Использовать PM2 для управления Node.js процессами
3. Настроить ротацию логов
4. Регулярно очищать старые данные из БД
5. Мониторить использование памяти TensorFlow.js
