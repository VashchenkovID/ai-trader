# Анализ обновления опционных данных

## Частота обновления

### Рекомендуемая частота: **Ежедневно (1 раз в день)**

**Обоснование:**
- Опционы меняются ежедневно (цены опционов), но не так часто как свечи
- IV (Implied Volatility) меняется постоянно, но для нейросети достаточно обновлять раз в день
- Чаще чем фундаментальные данные (квартально), но реже чем свечи (каждые несколько минут/часов)
- Оптимальное время: **01:00 утра** (до обновления кеша в 02:00)

### Сравнение с другими данными:
- **Свечи**: Каждые 4 часа (cache update)
- **Опционы**: Ежедневно в 01:00
- **Фундаментальные данные**: Квартально (вручную или по запросу)
- **Макро-данные**: Ежедневно в 10:00

## Реализованное решение

### 1. Автоматическое обновление (Cron задача)
- **Расписание**: Ежедневно в 01:00 (настраивается через `options_data_update_interval` в настройках)
- **Метод**: `SchedulerService.performOptionsDataUpdate()`
- **Сервис**: `OptionsDataService.updateOptionsForAllInstruments()`
- **Задержка**: 2 секунды между запросами для избежания rate limiting

### 2. Ручное обновление (API + Frontend)
- **API endpoint**: `POST /api/options-data/update-all`
- **Параметры**: 
  - `forceUpdate`: принудительное обновление (по умолчанию false)
  - `delayMs`: задержка между запросами (по умолчанию 2000ms)
  - `limit`: ограничение количества инструментов (по умолчанию null = все)
- **Frontend**: Кнопка "Обновить опционные данные" в настройках (вкладка "Квартальные данные")

### 3. Интеграция с кешем
- Опционы **НЕ** включены в `performCacheUpdate()` (обновление кеша свечей)
- Причина: Опционы обновляются реже и требуют больше времени
- Обновление опционов выполняется отдельной задачей для контроля частоты

## Преимущества решения

1. **Контролируемая частота**: Отдельная задача позволяет точно контролировать частоту обновления
2. **Настраиваемость**: Расписание настраивается через Settings (`options_data_update_interval`)
3. **Ручное обновление**: Возможность принудительного обновления через API или UI
4. **Мониторинг**: Уведомления в Telegram о статусе обновления
5. **Гибкость**: Возможность ограничить количество обрабатываемых инструментов для тестирования

## Настройки

### Добавить в Settings (если еще нет):
```javascript
{
  key: 'options_data_update_interval',
  value: '0 1 * * *', // Ежедневно в 01:00
  type: 'string',
  module: 'scheduler',
  description: 'Расписание обновления опционных данных (cron format)'
}
```

## Рекомендации

1. **Не включать в cache update**: Опционы обновляются отдельно для контроля частоты
2. **Мониторинг**: Следить за количеством ошибок при обновлении
3. **Оптимизация**: При большом количестве инструментов можно ограничить `limit` для постепенного обновления
4. **Fallback**: При отсутствии цены опциона используется историческая волатильность
