## ❌ Выявленные проблемы

### 1. Критические проблемы

#### Проблема 1: Неоптимальное соотношение Risk/Reward
**Текущее состояние:**
- Консервативная: 12% SL / 25% TP = **Risk/Reward = 1:2.08** ✅
- Умеренная: 6% SL / 12% TP = **Risk/Reward = 1:2.0** ✅
- Агрессивная: 3% SL / 6% TP = **Risk/Reward = 1:2.0** ✅

**Оценка:** Соотношения Risk/Reward выглядят хорошо (все > 1:2), но:
- ❌ Агрессивная стратегия имеет очень узкий стоп-лосс (3%) - высокая вероятность ложных срабатываний
- ❌ Нет учета реальной волатильности инструмента при выборе параметров

#### Проблема 2: Логика выбора стратегий неполная
**Код:** `TradingStrategy.getStrategyForRecommendation()` и `StrategyAllocationService.getStrategyForRecommendation()`

**Проблемы:**
- ❌ В `TradingStrategy.getStrategyForRecommendation()` есть пропуски в диапазонах:
  - `confidence >= 0.8 && score <= 0.75` → не подходит ни под одну стратегию
  - `confidence >= 0.5 && score < 0.5` → не подходит ни под одну стратегию
  - `confidence < 0.5 && score >= 0.5` → не подходит ни под одну стратегию
- ❌ Два разных метода с разной логикой могут давать разные результаты
- ✅ `StrategyAllocationService.getStrategyForRecommendation()` имеет лучшую логику с проверкой `minConfidence` и `minScore`

#### Проблема 3: Отсутствие валидации Risk/Reward
**Текущее состояние:**
- ❌ Нет проверки, что `takeProfitPercent` > `stopLossPercent`
- ❌ Нет проверки минимального соотношения Risk/Reward (рекомендуется ≥ 1:2)
- ❌ Нет предупреждения при создании стратегии с плохим соотношением

#### Проблема 4: Неоптимальный расчет размера позиции
**Текущий подход:** Максимум 10% от бюджета стратегии на позицию

**Проблемы:**
- ❌ Фиксированный процент не учитывает качество сигнала
- ❌ Не используется Kelly Criterion для оптимизации размера позиции
- ❌ Корректировка на основе confidence (1.2x или 0.8x) слишком простая
- ❌ Нет учета Win Rate стратегии при расчете размера

### 2. Средние проблемы

#### Проблема 5: Отсутствие учета волатильности
**Текущее состояние:**

- ❌ Но при выборе стратегии не учитывается волатильность инструмента
- ❌ Высоковолатильные инструменты могут требовать более широких стоп-лоссов

#### Проблема 8: Перебалансировка может быть слишком частой

## 🔧 Рекомендации по улучшению

### Приоритет 1: Критические исправления

#### 1.1 Улучшить логику выбора стратегий
**Проблема:** Пропуски в диапазонах confidence/score

**Решение:**
```javascript
// Улучшенная логика в TradingStrategy.getStrategyForRecommendation()
if (confidence >= 0.8 && score >= 0.75) {
    // Агрессивная
} else if (confidence >= 0.6 && score >= 0.6) {
    // Умеренная
} else if (confidence >= 0.5 && score >= 0.5) {
    // Консервативная
} else {
    // Ни одна стратегия не подходит - вернуть null или самую консервативную
    return null; // или найти самую консервативную с минимальными требованиями
}
```

**Действие:** Объединить логику из обоих методов, использовать одну унифицированную функцию.

#### 1.2 Добавить валидацию Risk/Reward
**Решение:**
- При создании/обновлении стратегии проверять:
  - `takeProfitPercent > stopLossPercent`
  - `takeProfitPercent / stopLossPercent >= 1.5` (минимальное соотношение 1:1.5)
- Предупреждать пользователя, если соотношение слишком низкое

**Действие:** Добавить валидацию в модель `TradingStrategy` или в метод обновления.

#### 1.3 Добавить Kelly Criterion для расчета размера позиции
**Проблема:** Фиксированный 10% не оптимален

**Решение:**
```javascript
// В StrategyAllocationService.calculatePositionSize()
// Использовать Kelly Criterion: f = (bp - q) / b
// где:
// - b = winAmount / lossAmount (profit factor)
// - p = winRate (вероятность выигрыша)
// - q = 1 - p (вероятность проигрыша)

const kellyPercent = calculateKellyCriterion(winRate, avgWin, avgLoss);
const maxPositionSize = Math.min(
    availableBudget * kellyPercent,
    availableBudget * 0.1 // Максимум 10% как ограничение
);
```

**Действие:** Интегрировать расчет Kelly % в `calculatePositionSize()`.

#### 1.4 Улучшить параметры агрессивной стратегии
**Проблема:** 3% стоп-лосс слишком узкий

**Решение:**
- Увеличить `stopLossPercent` до 5%
- Увеличить `takeProfitPercent` до 10% (сохранить соотношение 1:2)
- Или использовать динамический стоп на основе ATR (уже есть, но нужно проверять использование)

### Приоритет 2: Важные улучшения

#### 2.1 Добавить учет волатильности при выборе стратегии
**Решение:**
- При высоком ATR → использовать более широкие стоп-лоссы или более консервативную стратегию
- При низком ATR → можно использовать агрессивную стратегию

```javascript
// В getStrategyForRecommendation()
const atr = await calculateATRForInstrument(figi);
const atrPercent = (atr / currentPrice) * 100;

// Если волатильность высокая (> 5%), снижаем агрессивность
if (atrPercent > 5 && strategyType === 'aggressive') {
    strategyType = 'moderate';
}
```

#### 2.2 Добавить проверку корреляции позиций
**Решение:**
- В `calculatePositionSize()` проверять корреляцию с существующими позициями в стратегии
- Если корреляция высокая (> 0.7), уменьшать размер позиции или блокировать вход

#### 2.3 Адаптировать параметры под временной горизонт
**Решение:**
- Для `timeframe: 'long'` → более широкие стоп-лоссы (например, ×1.5)
- Для `timeframe: 'short'` → более узкие стоп-лоссы (например, ×0.8)

```javascript
// При расчете стоп-лосса учитывать timeframe
let adjustedStopLoss = stopLossPercent;
if (strategy.timeframe === 'long') {
    adjustedStopLoss *= 1.5; // Шире стоп для долгосрочных
} else if (strategy.timeframe === 'short') {
    adjustedStopLoss *= 0.8; // Уже стоп для краткосрочных
}
```

#### 2.4 Добавить защиту от частых перебалансировок
**Решение:**
- Минимальный интервал между перебалансировками (например, 7 дней)
- Минимальный порог изменения бюджета для перебалансировки (например, 5%)
