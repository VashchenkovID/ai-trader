# Руководство по валидации входа и обучению системы

## Проблема: Система не дает покупать акции из-за валидации

Система использует `EntryOptimizationService` для проверки условий входа в позицию. Это защитный механизм, который предотвращает входы в неблагоприятных условиях.

## Требования валидации входа

### 1. Подтверждающие индикаторы (минимум 2 из 3)

Система проверяет 3 технических индикатора:
- **RSI (Relative Strength Index)**
- **MACD (Moving Average Convergence Divergence)**
- **Bollinger Bands**

**Требование:** Минимум 2 индикатора должны подтверждать сигнал.

#### Критерии для BUY:
- **RSI:** < 30 (перепроданность) ИЛИ 40-60 (нейтральная зона)
- **MACD:** MACD > signal И MACD > 0 (бычий тренд)
- **Bollinger Bands:** Цена в нижней части полосы (перепроданность)

#### Критерии для SELL:
- **RSI:** > 70 (перекупленность) ИЛИ 40-60 (нейтральная зона)
- **MACD:** MACD < signal И MACD < 0 (медвежий тренд)
- **Bollinger Bands:** Цена в верхней части полосы (перекупленность)

### 2. Объем торгов (минимум 80% от среднего)

Система проверяет текущий объем торгов относительно среднего за последние 20 свечей.

**Требование:** Текущий объем должен быть ≥ 80% от среднего объема.

### 3. Ожидание коррекции (опционально)

Если включено, система может рекомендовать подождать коррекции цены для лучшего входа.

## Время для корректного обучения и анализа

### Минимальные требования к данным

#### Для базовой нейросети:
- **Абсолютный минимум:** 5 свечей (очень низкая точность)
- **Минимально приемлемо:** 15-20 свечей
- **Рекомендуется:** 30-50 свечей
- **Оптимально:** 100+ свечей

#### Для полного ансамбля моделей:
- **LSTM (краткосрочная):** минимум 25 свечей
- **CNN (среднесрочная):** минимум 31 свеча
- **Transformer (долгосрочная):** минимум 85 свечей

### Временные рамки

#### Для одного инструмента:
- **Быстрое обучение (trainQuick):** 15 эпох, 60 дней данных → **5-15 минут**
- **Стандартное обучение:** 50-100 эпох, 180 дней данных → **30-60 минут**
- **Полное обучение ансамбля:** все модели → **1-3 часа**

#### Для накопления достаточных данных:
- **Минимум для работы:** 1-2 недели торговых дней (10-14 дней)
- **Рекомендуется:** 1-2 месяца (20-40 торговых дней)
- **Оптимально:** 3-6 месяцев (60-120 торговых дней)

### Когда система начнет давать рекомендации

1. **Сразу после установки:** Система может работать, но с низкой точностью
2. **После 1-2 недель:** Накапливается достаточно данных для базовых прогнозов
3. **После 1-2 месяцев:** Система достигает приемлемой точности
4. **После 3-6 месяцев:** Оптимальная точность и стабильность

## Решения для тестирования

### Вариант 1: Временное ослабление валидации

Можно изменить настройки `EntryOptimizationService` через базу данных:

```sql
-- Уменьшить количество требуемых подтверждающих индикаторов
UPDATE settings 
SET value = '1' 
WHERE category = 'entry_optimization' AND key = 'minConfirmingIndicators';

-- Уменьшить минимальный объем
UPDATE settings 
SET value = '0.5' 
WHERE category = 'entry_optimization' AND key = 'minVolumeRatio';

-- Отключить ожидание коррекции
UPDATE settings 
SET value = 'false' 
WHERE category = 'entry_optimization' AND key = 'waitForCorrection';
```

### Вариант 2: Использование forceEntry через UI

В модальном окне создания заявки теперь есть опция **"Обойти валидацию входа"**, которая появляется:
- При ошибке валидации (когда система отклоняет заявку)
- При предупреждении о HOLD рекомендации

⚠️ **Внимание:** Использование этой опции обходит все проверки EntryOptimizationService. Используйте только для тестирования!

### Вариант 3: Использование forceEntry через API

При создании заявки можно передать опцию `forceEntry: true` для обхода валидации:

```javascript
// В API запросе
{
  "recommendationFigi": "BBG004S682Z6",
  "options": {
    "forceEntry": true,  // Обходит валидацию входа
    "quantity": 10,
    "strategyId": 1
  }
}
```

### Вариант 4: Отключение EntryOptimizationService

Можно временно отключить сервис, закомментировав его использование в `TradingRequestService.js`:

```javascript
// В server/src/services/TradingRequestService.js, строка ~89
// Закомментировать блок с EntryOptimizationService
/*
const EntryOptimizationService = (await import('./EntryOptimizationService.js')).default;
if (EntryOptimizationService && EntryOptimizationService.isInitialized) {
    // ... код валидации
}
*/
```

## Рекомендации

### Для тестирования (разработка):
1. Используйте чекбокс "Обойти валидацию входа" в UI (появляется при ошибке)
2. Или временно уменьшите требования валидации через БД
3. Или отключите `EntryOptimizationService` полностью

### Для продакшена:
1. Оставьте валидацию включенной для защиты от плохих входов
2. Дождитесь накопления достаточных данных (1-2 месяца)
3. Настройте параметры под вашу стратегию

## Текущие настройки по умолчанию

```javascript
{
    minConfirmingIndicators: 2,      // Минимум 2 индикатора
    minVolumeRatio: 0.8,              // 80% от среднего объема
    waitForCorrection: true,          // Ожидание коррекции включено
    rsiOversold: 30,                  // RSI < 30 для BUY
    rsiOverbought: 70,                // RSI > 70 для SELL
    rsiNeutral: 40,                   // RSI 40-60 нейтральная зона
    rsiNeutralUpper: 60,
    macdBullishThreshold: 0,         // MACD > 0 для бычьего тренда
    macdBearishThreshold: 0,         // MACD < 0 для медвежьего тренда
    bbLowerThreshold: 0.05,          // 5% ниже нижней полосы
    bbUpperThreshold: 0.05,          // 5% выше верхней полосы
    bbNeutralZone: 0.3,              // 30% нейтральная зона
    correctionThreshold: 0.02,       // Ожидать коррекцию 2%
    limitOrderOffset: 0.005,        // Лимитный ордер на 0.5% лучше
    volumeCheckPeriod: 20            // Период для среднего объема
}
```

## Как проверить текущие настройки

```sql
SELECT * FROM settings 
WHERE category = 'entry_optimization' 
ORDER BY key;
```

## Как ускорить накопление данных

1. **Запустите сбор данных вручную:**
   - Система автоматически собирает данные при анализе инструментов
   - Можно запустить анализ для всех инструментов через API

2. **Используйте быструю загрузку исторических данных:**
   - Система может загрузить исторические свечи из Tinkoff API
   - Это ускорит накопление данных для обучения

3. **Запустите обучение для всех инструментов:**
   ```bash
   # Через API endpoint для обучения
   POST /api/neural-network/train-all
   ```

## Выводы

- **Минимальное время для работы:** 1-2 недели
- **Рекомендуемое время:** 1-2 месяца
- **Оптимальное время:** 3-6 месяцев

## Почему система блокирует покупки?

Система проверяет:
1. **Технические индикаторы** - должны подтверждать сигнал (минимум 2 из 3)
2. **Объем торгов** - должен быть достаточным (≥80% от среднего)
3. **Коррекция** - может рекомендовать подождать лучшей цены

Это защищает от:
- Покупок на пиках (перекупленность)
- Покупок при низкой ликвидности
- Покупок в неблагоприятных условиях

## Рекомендации по настройке для начала работы

2. **Или используйте forceEntry** при создании заявок через UI (чекбокс появится при ошибке)

3. **После накопления данных (1-2 месяца)** верните настройки к рекомендуемым значениям

## Быстрое решение для тестирования

1. **Через UI:** При ошибке валидации установите чекбокс "Обойти валидацию входа"
2. **Через API:** Передайте `forceEntry: true` в опциях при создании заявки
3. **Через настройки БД:** Временно уменьшите требования валидации (см. Вариант 1)
