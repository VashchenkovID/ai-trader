# План реализации регулярного бэктестинга стратегий

## Обзор

Реализация системы регулярного бэктестинга для торговых стратегий с целью выявления проблемных стратегий до потери капитала и автоматической оптимизации распределения бюджета.

## Текущее состояние системы

### Доступные данные
- **Исторические свечи**: `CachedCandle` (DAY, HOUR интервалы) - до 12+ месяцев данных
- **Сигналы**: `CachedSignal` от Tinkoff API с ценами входа/выхода, стоп-лоссами
- **Рекомендации AI**: `Recommendation` с confidence, score, анализом горизонтов
- **Позиции**: `PositionStrategy` с entryDate, exitDate, resultPercent
- **Торговые заявки**: `TradingRequest` с полной историей

### Существующие метрики
- `ProfitabilityTracker` - отслеживает метрики производительности
- `PerformanceAnalyzer` - анализирует торговые результаты
- Расчеты: Sharpe Ratio, Win Rate, Max Drawdown, Profit Factor

### Структура стратегий
- **TradingStrategy** модель:
  - Типы: conservative, moderate, aggressive
  - Параметры: budgetAllocation, minConfidence, minScore, stopLossPercent, atrMultiplier, takeProfitPercent, maxPositions, isActive
  - Связь с позициями через `PositionStrategy.strategyId`

## Архитектура решения

### 1. BacktestingService (`server/src/services/BacktestingService.js`)

Основной сервис для выполнения бэктестинга стратегий.

#### Основные методы:

**1.1. `backtestStrategy(strategyId, options)`**
- Симуляция торговли стратегией на исторических данных
- Параметры:
  - `strategyId` - ID стратегии для тестирования
  - `startDate` - Дата начала теста (по умолчанию: 6 месяцев назад)
  - `endDate` - Дата окончания теста (по умолчанию: сейчас)
  - `initialCapital` - Начальный капитал (по умолчанию: из настроек портфеля)
  - `instruments` - Список FIGI для тестирования (по умолчанию: все активные инструменты)
- Возвращает:
  ```javascript
  {
    strategyId,
    strategyName,
    period: { startDate, endDate },
    metrics: {
      totalReturn: number,        // Общая доходность в %
      totalProfit: number,        // Общая прибыль в рублях
      totalTrades: number,        // Количество сделок
      winRate: number,            // Процент прибыльных сделок
      avgWin: number,             // Средняя прибыль на сделку
      avgLoss: number,            // Средний убыток на сделку
      profitFactor: number,       // Отношение прибыли к убыткам
      sharpeRatio: number,        // Коэффициент Шарпа
      maxDrawdown: number,        // Максимальная просадка в %
      maxDrawdownDuration: number, // Длительность максимальной просадки в днях
      volatility: number,          // Волатильность доходности
      calmarRatio: number,        // Отношение доходности к максимальной просадке
      sortinoRatio: number        // Коэффициент Сортино
    },
    trades: Array<{
      figi: string,
      ticker: string,
      entryDate: Date,
      exitDate: Date,
      entryPrice: number,
      exitPrice: number,
      quantity: number,
      pnl: number,
      pnlPercent: number,
      exitReason: 'target' | 'stoploss' | 'timeout' | 'signal_end'
    }>,
    equityCurve: Array<{ date: Date, value: number }>, // Кривая капитала
    monthlyReturns: Array<{ month: string, return: number }>,
    alerts: Array<{ type: string, message: string, severity: string }>
  }
  ```

**1.2. `walkForwardAnalysis(strategyId, options)`**
- Walk-forward анализ для проверки стабильности стратегии
- Параметры:
  - `strategyId` - ID стратегии
  - `trainingPeriod` - Период обучения в месяцах (по умолчанию: 3)
  - `testingPeriod` - Период тестирования в месяцах (по умолчанию: 1)
  - `totalPeriod` - Общий период анализа в месяцах (по умолчанию: 12)
- Методология:
  1. Разделение данных на окна: обучение → тестирование → сдвиг
  2. Тестирование стратегии на каждом окне тестирования
  3. Анализ стабильности метрик между окнами
  4. Выявление деградации производительности
- Возвращает:
  ```javascript
  {
    strategyId,
    windows: Array<{
      trainingPeriod: { start: Date, end: Date },
      testingPeriod: { start: Date, end: Date },
      metrics: {...}, // Метрики для этого окна
      stability: {
        consistency: number,      // Консистентность метрик (0-1)
        degradation: number,      // Деградация производительности (0-1)
        trend: 'improving' | 'stable' | 'degrading'
      }
    }>,
    overallStability: {
      averageReturn: number,
      returnStdDev: number,
      consistencyScore: number,   // Общая оценка стабильности (0-1)
      isStable: boolean,
      recommendation: 'keep' | 'optimize' | 'disable'
    }
  }
  ```

**1.3. `backtestMultipleStrategies(strategyIds, options)`**
- Бэктестинг нескольких стратегий одновременно для сравнения
- Возвращает сравнение производительности стратегий

**1.4. `simulateTrading(figi, strategy, startDate, endDate, initialCapital)`**
- Внутренний метод для симуляции торговли на одном инструменте
- Логика:
  1. Получение исторических свечей для периода
  2. Получение сигналов/рекомендаций для периода
  3. Симуляция входа по сигналам с учетом параметров стратегии
  4. Симуляция выхода по стоп-лоссу, тейк-профиту или окончанию сигнала
  5. Расчет PnL для каждой сделки

**1.5. `calculateMetrics(trades, equityCurve)`**
- Расчет всех метрик производительности на основе сделок и кривой капитала

**1.6. `generateReport(backtestResult)`**
- Генерация детального отчета о результатах бэктестинга
- Формат: Markdown с графиками (текстовые ASCII-графики или ссылки на визуализацию)

### 2. Модель BacktestResult (`server/src/models/BacktestResult.js`)

Модель для хранения результатов бэктестинга в БД.

```javascript
{
  id: INTEGER (PK),
  strategyId: INTEGER (FK -> TradingStrategy),
  backtestType: ENUM('full', 'walk_forward'),
  startDate: DATE,
  endDate: DATE,
  initialCapital: FLOAT,
  finalCapital: FLOAT,
  totalReturn: FLOAT,
  totalTrades: INTEGER,
  winRate: FLOAT,
  sharpeRatio: FLOAT,
  maxDrawdown: FLOAT,
  metrics: JSON,              // Полные метрики
  trades: JSON,               // Массив сделок
  equityCurve: JSON,          // Кривая капитала
  report: TEXT,               // Сгенерированный отчет
  alerts: JSON,               // Массив предупреждений
  createdAt: DATE,
  updatedAt: DATE
}
```

### 3. Интеграция с SchedulerService

**3.1. Новая cron-задача: `weeklyBacktestTask`**
- Расписание: каждое воскресенье в 2:00 AM (`'0 2 * * 0'`)
- Выполняет:
  1. Бэктестинг всех активных стратегий за последние 6 месяцев
  2. Walk-forward анализ за последние 12 месяцев
  3. Сравнение результатов с предыдущими бэктестами
  4. Выявление деградирующих стратегий
  5. Генерация отчетов
  6. Отправка уведомлений в Telegram

**3.2. Метод `performWeeklyBacktest()`**
- Координирует выполнение бэктестинга
- Обработка ошибок и логирование

### 4. Интеграция с StrategyAllocationService

**4.1. Автоматическое отключение деградирующих стратегий**
- Метод `checkStrategyHealth(strategyId)`:
  - Анализирует последние результаты бэктестинга
  - Проверяет метрики на деградацию
  - Возвращает рекомендацию: 'keep' | 'optimize' | 'disable'
  
**4.2. Автоматическая оптимизация бюджета**
- Метод `optimizeBudgetAllocation()`:
  - Использует результаты бэктестинга для перераспределения бюджета
  - Увеличивает бюджет для успешных стратегий
  - Уменьшает бюджет для деградирующих стратегий

**4.3. Метод `applyBacktestRecommendations()`**
- Применяет рекомендации из бэктестинга:
  - Отключение стратегий с критической деградацией
  - Оптимизация параметров стратегий
  - Перераспределение бюджета

### 5. Отчетность и уведомления

**5.1. Генерация отчетов**
- Формат: Markdown с таблицами и метриками
- Содержание:
  - Сводка по всем стратегиям
  - Детальные метрики для каждой стратегии
  - Графики кривых капитала (текстовые или ссылки)
  - Рекомендации по оптимизации
  - Предупреждения о деградации

**5.2. Telegram уведомления**
- Еженедельный отчет в Telegram
- Критические предупреждения о деградации стратегий
- Рекомендации по действиям

### 6. API endpoints

**6.1. `GET /api/backtest/results/:strategyId`**
- Получение последних результатов бэктестинга для стратегии

**6.2. `POST /api/backtest/run/:strategyId`**
- Запуск бэктестинга для конкретной стратегии вручную

**6.3. `GET /api/backtest/compare`**
- Сравнение результатов бэктестинга всех стратегий

**6.4. `GET /api/backtest/report/:strategyId`**
- Получение детального отчета по бэктестингу

## Детали реализации

### Симуляция торговли

**Вход в позицию:**
1. Проверка наличия сигнала/рекомендации с BUY
2. Проверка соответствия параметрам стратегии (minConfidence, minScore)
3. Проверка доступного бюджета
4. Расчет размера позиции на основе бюджета стратегии
5. Симуляция покупки по цене закрытия свечи

**Выход из позиции:**
1. Проверка достижения целевой цены (takeProfitPercent)
2. Проверка срабатывания стоп-лосса (stopLossPercent или ATR-based)
3. Проверка окончания действия сигнала (endDt)
4. Проверка таймаута (для стратегий с targetTimeframe)
5. Симуляция продажи по цене закрытия свечи

**Управление капиталом:**
- Учет комиссий (если применимо)
- Учет проскальзывания (slippage) - опционально
- Ограничение размера позиции (maxPositions)
- Распределение бюджета между стратегиями

### Расчет метрик

**Основные метрики:**
- `totalReturn` = (finalCapital - initialCapital) / initialCapital * 100
- `winRate` = profitableTrades / totalTrades * 100
- `profitFactor` = totalProfit / Math.abs(totalLoss)
- `sharpeRatio` = (averageReturn - riskFreeRate) / stdDevReturn * sqrt(252)
- `maxDrawdown` = максимальная просадка от пика капитала
- `calmarRatio` = annualReturn / maxDrawdown
- `sortinoRatio` = (averageReturn - riskFreeRate) / downsideDeviation * sqrt(252)

**Стабильность (для walk-forward):**
- `consistency` = 1 - (stdDevReturns / averageReturn) (нормализовано)
- `degradation` = сравнение метрик последних окон с первыми
- `trend` = анализ тренда метрик по окнам

### Критерии деградации стратегии

Стратегия считается деградирующей, если:
1. **Критическая деградация** (автоматическое отключение):
   - Win Rate упал ниже 40% в последних 3 окнах
   - Sharpe Ratio упал ниже 0.5 в последних 3 окнах
   - Max Drawdown превысил 30% в последних 3 окнах
   - Total Return отрицательный в последних 3 окнах

2. **Предупреждение** (требует внимания):
   - Win Rate упал ниже 50% в последних 2 окнах
   - Sharpe Ratio упал ниже 1.0 в последних 2 окнах
   - Max Drawdown превысил 20% в последних 2 окнах
   - Консистентность метрик ниже 0.6

3. **Оптимизация** (рекомендуется):
   - Небольшая деградация метрик
   - Нестабильность производительности между окнами

## Риски и ограничения

### Риски:
1. **Недостаток исторических данных** - некоторые инструменты могут иметь ограниченную историю
2. **Look-ahead bias** - необходимо убедиться, что используются только данные, доступные на момент принятия решения
3. **Overfitting** - стратегии могут быть переоптимизированы под исторические данные
4. **Производительность** - бэктестинг может быть ресурсоемким для большого количества стратегий и инструментов

### Ограничения:
1. Симуляция не учитывает реальные задержки исполнения
2. Проскальзывание может быть недооценено
3. Ликвидность инструментов не учитывается
4. Комиссии могут отличаться от реальных
