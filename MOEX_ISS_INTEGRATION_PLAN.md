# План интеграции MOEX ISS API для цен на сырье

## Цель
Интегрировать MOEX ISS API для получения данных о ценах на сырьевые товары (нефть, газ, металлы) и добавления их в макро-фичи нейросети.

## Текущее состояние

### Модель данных
- `MacroIndicator` модель уже поддерживает тип `'oil_price'` в ENUM
- Нужно добавить новый тип `'commodity_price'` для унификации

### Сервисы
- `MacroDataService` - основной сервис для работы с макро-данными
- `OptimizedDataService.getMacroFeatures()` - получение макро-фичей для нейросети (сейчас 8 фичей)

### Парсеры
- `macroDataParsers.js` - содержит парсеры для различных источников данных
- Есть примеры парсеров для CBR, Росстат, MOEX (RVI)

### Этап 2: Создание парсера MOEX ISS API

#### 2.1 Создание функции парсинга
**Файл:** `server/src/utils/macroDataParsers.js`

**Функция:** `parseMoexCommodityJson(jsonData, commodityType)`

**Параметры:**
- `jsonData` - JSON ответ от MOEX ISS API
- `commodityType` - тип сырья ('oil', 'gas', 'gold', 'silver', 'copper', 'nickel', 'aluminum')

**Возвращает:**
```javascript
Array<{
  date: Date,
  value: number, // цена закрытия (CLOSE)
  metadata: {
    commodityType: string,
    commodityCode: string,
    open: number,
    high: number,
    low: number,
    volume: number,
    previousValue: number,
    change: number,
    changePercent: number
  }
}>
```

**Формат ответа MOEX ISS API:**
```json
{
  "history": {
    "columns": ["TRADEDATE", "SECID", "OPEN", "LOW", "HIGH", "CLOSE", "SETTLEPRICE", "VOLUME", "OPENPOSITION"],
    "data": [
      ["2024-01-15", "BR-1.24", 75.50, 74.20, 76.10, 75.80, 75.80, 1000, 5000],
      ...
    ]
  }
}
```

**Проблема:** Фьючерсы имеют сроки действия (например, BR-1.24, BR-2.24). Нужно получать актуальный ближайший фьючерс.

**Решение:** 
1. Получать список активных фьючерсов через `/iss/engines/futures/markets/forts/securities.json`
2. Находить ближайший активный фьючерс для каждого типа сырья
3. Использовать его для получения исторических данных

### Этап 3: Реализация метода получения данных в MacroDataService

#### 3.1 Метод получения активных фьючерсов
**Метод:** `async fetchActiveCommodityFutures()`

**Функционал:**
- Получает список всех активных фьючерсов на FORTS
- Фильтрует по кодам сырья (BR, NG, GD, SV, CU, NI, AL)
- Находит ближайший активный фьючерс для каждого типа
- Возвращает map: `{ oil: 'BR-1.24', gas: 'NG-2.24', ... }`

#### 3.2 Метод получения исторических данных
**Метод:** `async fetchMoexCommodityData(startDate, endDate)`

**Функционал:**
1. Получает список активных фьючерсов
2. Для каждого типа сырья:
   - Формирует URL для исторических данных
   - Делает запрос к MOEX ISS API
   - Парсит ответ через `parseMoexCommodityJson`
   - Сохраняет данные через `saveIndicator`

**URL формат:**
```
https://iss.moex.com/iss/history/engines/futures/markets/forts/securities/{secid}.json
?from={startDate}&till={endDate}
&iss.meta=off
&iss.only=history
```

## Технические детали

### Обработка истекающих фьючерсов
**Проблема:** Фьючерсы имеют срок действия (месяц). Нужно автоматически переключаться на следующий активный контракт.

**Решение:**
1. При каждом обновлении получать список активных фьючерсов
2. Находить ближайший активный фьючерс для каждого типа сырья
3. Если текущий фьючерс истек, автоматически переключиться на следующий
4. Сохранять в `metadata` информацию о фьючерс-контракте

### Нормализация цен
**Проблема:** Разные валюты и диапазоны цен для разных видов сырья.

**Решение:**
- Хранить оригинальные цены в `value` (в валюте контракта)
- В `metadata` указывать валюту и диапазон нормализации
- Нормализовать при создании фичей для нейросети

### Обработка ошибок
- Если MOEX ISS API недоступен, использовать последние известные значения
- Если данные для конкретного типа сырья отсутствуют, использовать средние значения (0.5 после нормализации)
- Логировать ошибки, но не прерывать процесс обучения

### Производительность
- Кешировать список активных фьючерсов на 1 час
- Использовать batch запросы где возможно
- Добавить rate limiting для запросов к MOEX ISS API (хотя официального лимита нет)
