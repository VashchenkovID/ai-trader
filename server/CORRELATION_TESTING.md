# Инструкция по тестированию системы контроля корреляций

## Подготовка

### 1. Запуск миграции БД

Перед тестированием необходимо создать таблицу для кеширования корреляций:

```bash
cd server
npm run migrate:correlation-cache
```

Или напрямую:

```bash
node migrations/create-correlation-cache-table.js
```

### 2. Проверка наличия данных

Убедитесь, что в кеше есть инструменты. Если кеш пуст, запустите обновление:

```bash
# Запустите сервер, который автоматически обновит кеш
npm start
```

Или используйте скрипт обновления кеша (если есть).

## Ожидаемые результаты

### Успешный тест

```
✅ Все основные тесты пройдены успешно!
```

### Возможные проблемы

#### 1. Недостаточно инструментов в кеше

```
❌ Недостаточно инструментов в кеше (нужно минимум 2)
💡 Запустите обновление кеша инструментов
```

**Решение:** Запустите сервер для обновления кеша или используйте API для добавления инструментов.

#### 2. Ошибка подключения к БД

```
❌ Database connection failed
```

**Решение:** 
- Проверьте настройки в `.env` файле
- Убедитесь, что PostgreSQL запущен
- Проверьте права доступа к БД

#### 3. Таблица correlation_cache не существует

```
❌ relation "correlation_cache" does not exist
```

**Решение:** Запустите миграцию:
```bash
npm run migrate:correlation-cache
```

#### 4. Недостаточно исторических данных

```
⚠️ Недостаточно данных для расчета корреляции
```

**Решение:** 
- Подождите накопления данных в кеше свечей
- Убедитесь, что CacheService обновляет свечи регулярно
- Проверьте, что инструменты имеют достаточную историю торгов

## Ручное тестирование через API

После успешного прохождения тестов можно протестировать систему через API:

### 1. Проверка корреляционного риска при валидации сигнала

Система автоматически проверяет корреляцию при валидации торгового сигнала через `RiskManagementService.validateOrder()`.

### 2. Проверка корреляции портфеля

Система автоматически рассчитывает корреляцию портфеля при анализе через `CapitalAllocationStrategy.analyzePortfolio()`.

## Мониторинг работы системы

### Логи

Следите за логами сервера для проверки работы системы:

```
🔗 Инициализация CorrelationService...
✅ CorrelationService инициализирован
🔄 Предварительный расчет корреляций для 50 инструментов...
✅ Предварительный расчет завершен: рассчитано 1200, из кеша 0, ошибок 0
```

### Cron задача

Предварительный расчет корреляций запускается каждое воскресенье в 2:00 (настраивается через `correlation_precalc_schedule`).

### Проверка кеша

Можно проверить содержимое кеша корреляций напрямую:

```sql
SELECT 
    figi1, 
    figi2, 
    correlation, 
    period, 
    "calculatedAt", 
    "expiresAt"
FROM correlation_cache
WHERE "expiresAt" > NOW()
ORDER BY "calculatedAt" DESC
LIMIT 10;
```

## Настройка параметров

Параметры системы можно настроить через Settings:

- `correlation_period` - период расчета корреляции (по умолчанию 30 дней)
- `correlation_cache_ttl_hours` - время жизни кеша в часах (по умолчанию 24 часа)
- `correlation_min_data_points` - минимальное количество точек данных (по умолчанию 20)
- `correlation_threshold` - порог высокой корреляции (по умолчанию 0.7)
- `portfolio_correlation_threshold` - порог корреляции портфеля для блокировки (по умолчанию 0.7)
- `correlation_precalc_schedule` - расписание предварительного расчета (по умолчанию '0 2 * * 0')

### Проверка данных свечей

Убедитесь, что в кеше есть свечи для тестируемых инструментов:

```sql
SELECT figi, COUNT(*) as candle_count, MIN(time) as first_candle, MAX(time) as last_candle
FROM cached_candles
WHERE figi IN ('BBG004730N88', 'BBG004730ZJ9')
GROUP BY figi;
```
