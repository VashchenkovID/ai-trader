# Тестирование LoggerService

## Описание

Тестовый скрипт проверяет работу централизованного логирования:
- Инициализацию LoggerService
- Базовое логирование (info, warn, debug)
- Логирование с контекстом (requestId, userId)
- Дочерние логгеры
- Специализированные методы (logDatabase, logApiCall, logCritical)
- Трассировку HTTP запросов
- Создание файлов логов

## Как запустить тесты

### Вариант 1: Через тестовый скрипт

```bash
cd server
node test-logging.js
```

### Вариант 2: Вручную через браузер/curl

1. **Проверьте health endpoint:**
   ```bash
   curl http://localhost:3001/health
   ```
   Проверьте заголовок `X-Request-ID` в ответе.

2. **Проверьте API endpoint:**
   ```bash
   curl http://localhost:3001/api/monitoring/health
   ```
   Проверьте заголовок `X-Request-ID` и логи в `server/logs/`.

## Что проверяется

### 1. Инициализация LoggerService
- Проверяет, что сервис успешно инициализирован
- Выводит статистику сервиса

### 2. Базовое логирование
- Тестирует методы `info`, `warn`, `debug`
- Проверяет запись в файлы логов

### 3. Логирование с контекстом
- Устанавливает контекст с `requestId` и `userId`
- Проверяет получение контекста
- Очищает контекст после использования

### 4. Дочерний логгер
- Создает дочерний логгер с фиксированным контекстом
- Проверяет автоматическое добавление контекста

### 5. Специализированные методы
- `logDatabase` - логирование операций с БД
- `logApiCall` - логирование вызовов внешних API
- `logCritical` - логирование критических ошибок

### 6. Request ID в HTTP запросах
- Проверяет наличие заголовка `X-Request-ID` в ответах
- Проверяет уникальность requestId для каждого запроса

### 7. Логирование HTTP запросов
- Проверяет автоматическое логирование всех запросов
- Проверяет логирование медленных запросов (>1 секунды)

### 8. Файлы логов
- Проверяет создание директории `server/logs/`
- Проверяет наличие файлов логов

### Файлы логов

После тестирования должны быть созданы файлы в `server/logs/`:

- `combined.log` - Все логи уровня info и выше
- `error.log` - Только ошибки
- `exceptions.log` - Необработанные исключения (если были)
- `rejections.log` - Необработанные Promise rejections (если были)

## Проверка логов

### Просмотр логов в реальном времени

```bash
# Windows (PowerShell)
Get-Content server\logs\combined.log -Wait -Tail 50

# Linux/Mac
tail -f server/logs/combined.log
```

### Поиск по логам

```bash
# Поиск ошибок
grep "error" server/logs/combined.log

# Поиск по requestId
grep "req_12345" server/logs/combined.log

# Поиск по сервису
grep "\"service\":\"TestService\"" server/logs/combined.log
```

## Troubleshooting

### LoggerService не инициализирован

**Проблема:** `LoggerService.isInitialized === false`

**Решение:**
1. Убедитесь, что LoggerService добавлен в ServiceManager
2. Проверьте, что сервер запущен и сервисы инициализированы
3. Проверьте права на запись в директорию `server/logs/`

### Request ID не устанавливается

**Проблема:** Заголовок `X-Request-ID` отсутствует в ответах

**Решение:**
1. Убедитесь, что `requestTracing` middleware подключен в `app.js`
2. Проверьте порядок middleware (requestTracing должен быть до routes)

### Файлы логов не создаются

**Проблема:** Директория `server/logs/` пуста

**Решение:**
1. Проверьте права на запись в директорию
2. Убедитесь, что LoggerService инициализирован
3. Проверьте переменную окружения `LOG_LEVEL`

### Слишком много логов

**Проблема:** Файлы логов растут очень быстро

**Решение:**
1. Увеличьте `LOG_LEVEL` до `warn` или `error`
2. Проверьте, не логируете ли вы в циклах
3. Используйте `debug` вместо `info` для отладочной информации

## Дополнительные проверки

### Проверка структуры логов

Откройте `server/logs/combined.log` и проверьте формат:

```json
{
  "timestamp": "2025-01-27 12:34:56.789",
  "level": "info",
  "message": "Тестовое информационное сообщение",
  "service": "ai-trader",
  "environment": "development",
  "test": "basic-logging",
  "service": "TestService"
}
```

### Проверка ротации логов

1. Создайте большой объем логов
2. Дождитесь достижения 20MB
3. Проверьте создание файлов `combined.log.1`, `combined.log.2` и т.д.

### Проверка контекста

В логах должны автоматически добавляться:
- `requestId` - для HTTP запросов
- `userId` - если пользователь авторизован
- `service` - если используется дочерний логгер
