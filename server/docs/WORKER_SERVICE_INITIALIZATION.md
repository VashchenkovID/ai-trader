# Оптимизация инициализации сервисов в воркерах

## Проблема

Каждый воркер (worker thread) работал в изолированном потоке и заново инициализировал все сервисы для себя. Это приводило к:
- Дублированию подключений к базе данных
- Дублированию загрузки моделей TensorFlow
- Избыточному использованию памяти
- Медленной инициализации воркеров

## Решение

Реализована система отслеживания глобальной инициализации сервисов через файловую систему (`ServiceInitializationTracker`), которая позволяет воркерам проверять, не инициализирован ли сервис уже в основном процессе.

### Компоненты решения

1. **ServiceInitializationTracker** (`server/src/utils/ServiceInitializationTracker.js`)
   - Отслеживает инициализацию сервисов через файл `.service-init-tracker.json`
   - Проверяет, не инициализирован ли сервис глобально
   - Автоматически очищает устаревшие записи

2. **Обновленный ServiceManager**
   - Автоматически отмечает сервисы как глобально инициализированные при инициализации в основном процессе
   - Поддерживает легковесную инициализацию для воркеров (если сервис поддерживает `initializeLightweight()`)
   - Определяет, работает ли в воркере через флаг `process.env.WORKER`

3. **Обновленные воркеры**
   - Все воркеры проверяют глобальную инициализацию перед локальной
   - Используют легковесную инициализацию, если сервис уже инициализирован глобально
   - Устанавливают флаг `process.env.WORKER = 'true'` для идентификации

## Как это работает

1. **В основном процессе:**
   - При инициализации сервиса через `ServiceManager.initializeService()` сервис автоматически отмечается как глобально инициализированный
   - Информация сохраняется в файл `.service-init-tracker.json`

2. **В воркере:**
   - Воркер проверяет через `ServiceInitializationTracker.isServiceInitializedGlobally()` перед инициализацией
   - Если сервис уже инициализирован глобально:
     - Используется легковесная инициализация (если доступна)
     - Или пропускается тяжелая часть инициализации
   - Если сервис не инициализирован глобально - выполняется полная инициализация

## Преимущества

- ✅ Снижение дублирования инициализации
- ✅ Экономия памяти и ресурсов
- ✅ Более быстрая инициализация воркеров
- ✅ Автоматическая очистка устаревших записей
- ✅ Обратная совместимость - воркеры продолжают работать даже если трекер недоступен

## Примечания

- Воркеры все равно создают новые экземпляры сервисов (так как работают в изолированных потоках), но не выполняют тяжелую инициализацию
- Файл `.service-init-tracker.json` автоматически добавляется в `.gitignore`
- Записи об инициализации автоматически очищаются через 30 секунд после создания (настраивается через `INIT_TIMEOUT`)
