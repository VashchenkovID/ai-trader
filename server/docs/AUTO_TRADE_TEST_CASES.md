# Тест-кейсы для автоматического создания заявок с подтверждением через Telegram

## Обзор функционала

Система автоматически создает торговые заявки для высокоуверенных сигналов и отправляет их в Telegram для подтверждения пользователем.

## Условия для автоматического создания заявки

- **Confidence >= 0.85** (85%)
- **Score >= 0.8** (80%)
- **Agreement >= 0.9** (90% согласованность моделей)
- Заявка должна пройти все проверки RiskManagement

## Настройки

Настройки хранятся в таблице `settings`:
- `auto_trade_enabled` - включить/выключить автоматическое создание заявок (по умолчанию: `true`)
- `auto_trade_min_confidence` - минимальная уверенность (по умолчанию: `0.85`)
- `auto_trade_min_score` - минимальная оценка (по умолчанию: `0.8`)
- `auto_trade_min_agreement` - минимальная согласованность моделей (по умолчанию: `0.9`)

## Тест-кейсы

### TC-1: Автоматическое создание заявки при высоких показателях

**Предусловия:**
- Telegram бот настроен и инициализирован
- В БД есть рекомендация с высокими показателями (confidence >= 0.85, score >= 0.8)
- `auto_trade_enabled = true`

**Шаги:**
1. Система анализирует портфель и создает рекомендацию с высокими показателями
2. Рекомендация сохраняется в БД
3. Система проверяет условия для автоматического создания заявки
4. Если условия выполнены, создается торговая заявка
5. Заявка отправляется в Telegram с кнопками подтверждения/отклонения

**Ожидаемый результат:**
- Заявка создана в БД со статусом `pending`
- В Telegram отправлено сообщение с деталями заявки и кнопками
- Сообщение содержит: инструмент, цену, количество, сумму, параметры (confidence, score, agreement), стоп-лосс, тейк-профит

**Проверка:**
```sql
SELECT * FROM trading_requests 
WHERE figi = 'BBG004730N88' 
ORDER BY "createdAt" DESC 
LIMIT 1;
```

---

### TC-2: Заявка НЕ создается при низких показателях

**Предусловия:**
- Telegram бот настроен
- В БД есть рекомендация с низкими показателями (confidence < 0.85 или score < 0.8)

**Шаги:**
1. Система анализирует портфель и создает рекомендацию с низкими показателями
2. Рекомендация сохраняется в БД
3. Система проверяет условия для автоматического создания заявки

**Ожидаемый результат:**
- Заявка НЕ создается автоматически
- Сообщение в Telegram НЕ отправляется
- Рекомендация остается в БД без связанной заявки

**Проверка:**
```sql
SELECT COUNT(*) FROM trading_requests 
WHERE figi = 'BBG004730N88' 
AND "createdAt" > NOW() - INTERVAL '1 hour';
```

---

### TC-3: Подтверждение заявки через Telegram

**Предусловия:**
- В Telegram получено сообщение с заявкой и кнопками
- Заявка в статусе `pending`

**Шаги:**
1. Пользователь нажимает кнопку "✅ Подтвердить" в Telegram
2. Система обрабатывает callback `approve_request_{requestId}`
3. Заявка переводится в статус `approved`
4. Сообщение в Telegram обновляется с подтверждением

**Ожидаемый результат:**
- Заявка переведена в статус `approved`
- Сообщение в Telegram обновлено с текстом "ЗАЯВКА ПОДТВЕРЖДЕНА"
- Кнопки удалены из сообщения
- Заявка готова к исполнению

**Проверка:**
```sql
SELECT status, "approvedAt" FROM trading_requests 
WHERE id = '{requestId}';
```

---

### TC-4: Отклонение заявки через Telegram

**Предусловия:**
- В Telegram получено сообщение с заявкой и кнопками
- Заявка в статусе `pending`

**Шаги:**
1. Пользователь нажимает кнопку "❌ Отклонить" в Telegram
2. Система обрабатывает callback `reject_request_{requestId}`
3. Заявка переводится в статус `rejected`
4. Сообщение в Telegram обновляется с отклонением

**Ожидаемый результат:**
- Заявка переведена в статус `rejected`
- Указана причина отклонения: "Отклонено пользователем через Telegram"
- Сообщение в Telegram обновлено с текстом "ЗАЯВКА ОТКЛОНЕНА"
- Кнопки удалены из сообщения
- Заявка не будет исполнена

**Проверка:**
```sql
SELECT status, "rejectionReason", "rejectedAt" 
FROM trading_requests 
WHERE id = '{requestId}';
```

---

### TC-5: Попытка подтвердить уже обработанную заявку

**Предусловия:**
- Заявка уже подтверждена или отклонена

**Шаги:**
1. Пользователь пытается подтвердить заявку через Telegram
2. Система проверяет текущий статус заявки

**Ожидаемый результат:**
- Система обнаруживает, что заявка уже обработана
- Сообщение в Telegram обновляется с предупреждением: "Заявка уже обработана (статус: {status})"
- Статус заявки не изменяется

### TC-6: Проверка граничных значений

**Тест-кейсы для граничных значений:**

| Confidence | Score | Agreement | Ожидаемый результат |
|------------|-------|-----------|---------------------|
| 0.85 | 0.8 | 0.9 | ✅ Заявка создается |
| 0.84 | 0.8 | 0.9 | ❌ Заявка НЕ создается |
| 0.85 | 0.79 | 0.9 | ❌ Заявка НЕ создается |
| 0.85 | 0.8 | 0.89 | ❌ Заявка НЕ создается |
| 0.95 | 0.95 | 0.95 | ✅ Заявка создается |

**Проверка:**
Для каждого тест-кейса создать рекомендацию с указанными значениями и проверить, создается ли заявка.

### TC-7: Отключение автоматического создания заявок

**Предусловия:**
- `auto_trade_enabled = false`

**Шаги:**
1. Установить `auto_trade_enabled = false` в настройках
2. Система анализирует портфель и создает рекомендацию с высокими показателями
3. Система проверяет условия для автоматического создания заявки

**Ожидаемый результат:**
- Заявка НЕ создается автоматически, даже при высоких показателях
- Сообщение в Telegram НЕ отправляется

**Проверка:**
```sql
UPDATE settings SET value = 'false' WHERE key = 'auto_trade_enabled';
```

---

### TC-8: Изменение пороговых значений

**Предусловия:**
- Настройки доступны для изменения

**Шаги:**
1. Изменить `auto_trade_min_confidence` на 0.9
2. Изменить `auto_trade_min_score` на 0.85
3. Система анализирует портфель и создает рекомендацию с показателями:
   - confidence = 0.88
   - score = 0.82

**Ожидаемый результат:**
- Заявка НЕ создается (confidence 0.88 < 0.9)

**Проверка:**
```sql
UPDATE settings SET value = '0.9' WHERE key = 'auto_trade_min_confidence';
UPDATE settings SET value = '0.85' WHERE key = 'auto_trade_min_score';
```

---

### TC-9: Обработка ошибок при отправке в Telegram

**Предусловия:**
- Telegram бот не настроен или недоступен
- Рекомендация с высокими показателями создана

**Шаги:**
1. Система пытается отправить заявку в Telegram
2. Происходит ошибка (бот не инициализирован, сеть недоступна и т.д.)

**Ожидаемый результат:**
- Ошибка логируется, но не прерывает выполнение
- Заявка создается в БД со статусом `pending`
- Пользователь может подтвердить заявку через веб-интерфейс

---

### TC-10: Множественные заявки для разных инструментов

**Предусловия:**
- Несколько рекомендаций с высокими показателями для разных инструментов

**Шаги:**
1. Система анализирует портфель и создает несколько рекомендаций с высокими показателями
2. Для каждой рекомендации проверяются условия

**Ожидаемый результат:**
- Для каждой рекомендации, удовлетворяющей условиям, создается отдельная заявка
- В Telegram отправляется отдельное сообщение для каждой заявки
- Каждое сообщение содержит кнопки подтверждения/отклонения

## Интеграционные тесты

### IT-1: Полный цикл автоматического создания и подтверждения

**Шаги:**
1. Запустить анализ портфеля
2. Дождаться создания рекомендации с высокими показателями
3. Проверить создание заявки в БД
4. Проверить отправку сообщения в Telegram
5. Подтвердить заявку через Telegram
6. Проверить изменение статуса заявки на `approved`

**Ожидаемый результат:**
- Все шаги выполнены успешно
- Заявка готова к исполнению

---

### IT-2: Интеграция с RiskManagement

**Шаги:**
1. Создать рекомендацию с высокими показателями
2. Система проверяет заявку через RiskManagement
3. Если проверка не пройдена, заявка не создается

**Ожидаемый результат:**
- Заявка создается только если проходит все проверки RiskManagement
- Если проверка не пройдена, заявка не создается, даже при высоких показателях

## Команды для проверки

### Проверка настроек:
```sql
SELECT key, value FROM settings WHERE key LIKE 'auto_trade%';
```

### Проверка созданных заявок:
```sql
SELECT id, ticker, action, status, confidence, score, "createdAt" 
FROM trading_requests 
WHERE "createdAt" > NOW() - INTERVAL '1 hour'
ORDER BY "createdAt" DESC;
```

### Проверка рекомендаций:
```sql
SELECT figi, ticker, recommendation, confidence, score, "createdAt"
FROM recommendations
WHERE is_active = true
AND confidence >= 0.85
AND score >= 0.8
ORDER BY "createdAt" DESC;
```

---

## Известные ограничения

1. Заявка отправляется в Telegram только если бот инициализирован
2. Agreement может быть `null`, в этом случае проверка agreement пропускается
3. Заявка создается только для BUY/SELL рекомендаций, не для HOLD

---

## Логи для отладки

При включенном логировании проверьте следующие сообщения:
- `✅ Auto-trade conditions met for {ticker}` - условия выполнены
- `📱 Trading request sent to Telegram for approval: {requestId}` - заявка отправлена в Telegram
- `✅ Trading request {requestId} approved via Telegram` - заявка подтверждена
- `✅ Trading request {requestId} rejected via Telegram` - заявка отклонена
