# Руководство по торговым движкам

## Принцип работы торговых движков

### Архитектура системы

Система торговли состоит из трех основных компонентов:

1. **TradingEngine** - единый торговый движок для всех режимов
2. **TradingModeManager** - управление режимами торговли (paper/micro/real)
3. **RiskManagementService** - валидация и управление рисками

### Поток исполнения ордера

```
1. Сигнал → TradingEngine.executeOrder()
   ↓
2. Получение текущего режима → TradingModeManager.getCurrentMode()
   ↓
3. Валидация → RiskManagementService.validateOrder()
   ├─ Проверка экстренной остановки
   ├─ Проверка минимальной уверенности
   ├─ Проверка просадки
   ├─ Проверка последовательных убытков
   ├─ Проверка дневного убытка
   ├─ Расчет размера позиции (формула Келли)
   ├─ Проверка общего воздействия
   ├─ Проверка волатильности
   └─ Проверка корреляции
   ↓
4. Исполнение в зависимости от режима:
   ├─ paper → executePaperOrder() - виртуальное исполнение
   ├─ micro → executeMicroOrder() - реальное с ограничениями
   └─ real → executeRealOrder() - полное реальное исполнение
   ↓
5. Обновление статистики → RiskManagementService.updateStats()
   ↓
6. Уведомление → WebSocket + Telegram
```

## Режимы торговли

### 1. Paper (Бумажная торговля)
- **Назначение**: Тестирование стратегий без реальных денег
- **Особенности**:
  - Виртуальный портфель (1 млн руб по умолчанию)
  - Имитация проскальзывания и задержек
  - Расчет комиссий
  - Полная история сделок
- **Лимиты**:
  - Максимальный размер позиции: 5% от капитала
  - Максимальная просадка: 10%
  - Минимальная уверенность: 60%

### 2. Micro (Микро-торговля)
- **Назначение**: Реальная торговля с минимальными суммами
- **Особенности**:
  - Реальные ордера через Tinkoff API
  - Ограничение размера позиций
  - Строгий риск-менеджмент
- **Лимиты**:
  - Максимальный размер позиции: 2% от капитала
  - Максимальная просадка: 5%
  - Минимальная уверенность: 70%
  - Экстренная остановка: включена

### 3. Real (Реальная торговля)
- **Назначение**: Полноценная торговля
- **Особенности**:
  - Реальные ордера без ограничений по размеру
  - Максимальная защита
- **Лимиты**:
  - Максимальный размер позиции: 1% от капитала
  - Максимальная просадка: 3%
  - Минимальная уверенность: 80%
  - Экстренная остановка: включена

## Валидация ордеров

### Проверки RiskManagementService

1. **Экстренная остановка** - блокирует все сделки
2. **Минимальная уверенность** - проверяет confidence сигнала
3. **Максимальная просадка** - проверяет текущую просадку портфеля
4. **Последовательные убытки** - блокирует после N убытков подряд
5. **Дневной убыток** - ограничивает убытки за день
6. **Размер позиции** - рассчитывает оптимальный размер (формула Келли)
7. **Общее воздействие** - проверяет общую экспозицию портфеля
8. **Волатильность** - проверяет волатильность инструмента
9. **Корреляция** - проверяет корреляцию с существующими позициями

### Формула Келли для размера позиции

```
f = (bp - q) / b
где:
- b = odds (средний выигрыш / средний проигрыш)
- p = вероятность выигрыша (winRate)
- q = вероятность проигрыша (1 - winRate)

Консервативный подход: используем 1/4 от Келли
Максимум: 25% от капитала
```

## Комиссия

### Реальная комиссия Tinkoff
- **Ставка**: 0.3% от суммы сделки
- **Минимум**: 1 рубль
- **Примеры**:
  - Сделка на 10,000₽ → комиссия 30₽
  - Сделка на 100₽ → комиссия 1₽ (минимум)

### Учет комиссии в системе
- **При покупке**: Комиссия вычитается из наличных, PnL = -commission
- **При продаже**: Комиссия вычитается из выручки, PnL = (цена_продажи - средняя_цена_покупки_с_комиссией) * количество - commission
- **В статистике**: Комиссия учитывается в расчете прибыли/убытка

### Влияние комиссии
Комиссия 0.3% **не мешает**, потому что:
1. Это реальные условия торговли - стратегии должны работать с учетом комиссий
2. Правильно учитывается в расчетах PnL
3. Для крупных сделок (от 10,000₽) комиссия составляет 0.3%
4. Для мелких сделок минимальная комиссия 1₽ может быть значительной, но это реалистично

### Рекомендации
- Для тестирования стратегий используйте комиссию 0.3% - это даст реалистичные результаты
- Если нужно протестировать без комиссии, можно временно установить `commission: 0` в настройках paper режима
- Комиссия учитывается в валидации риск-менеджмента при расчете размера позиции

## Проблемы и исправления

### Проблема 1: Несоответствие типов в getCurrentMode()
**Проблема**: `getCurrentMode()` возвращает объект, но используется как строка
**Исправление**: Использовать `mode.mode` или изменить метод ✅

### Проблема 2: Неправильное использование портфеля в валидации
**Проблема**: Валидация всегда использует виртуальный портфель
**Исправление**: Передавать актуальный портфель в зависимости от режима ✅

### Проблема 3: Хардкод в calculateTotalExposure()
**Проблема**: Используется `estimatedValue = quantity * 1000`
**Исправление**: Получать реальные цены из currentPrices ✅

### Проблема 4: Неправильный расчет PnL в executePaperOrder()
**Проблема**: Не учитывает комиссию при покупке в средней цене
**Исправление**: Рассчитывать среднюю цену покупки с учетом комиссии ✅
