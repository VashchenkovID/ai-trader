# Стратегия обновления данных в режиме, близком к реальному времени

## Текущее состояние

### Обновление цен
- **Частота**: каждые 20 минут
- **Охват**: все инструменты (до 1000)
- **Метод**: `performPriceUpdate()` через `priceUpdateWorker.js`

### Обновление кеша
- **Инкрементальное**: раз в сутки (2:00)
- **Полное**: по кнопке (свечи за 2 года, сигналы 1000)

### Торговые часы
- **Частота**: каждые 15 минут
- **Охват**: несколько инструментов для проверки

## Рекомендуемая стратегия обновления

### 1. Цены акций (приоритетная задача)

#### 1.1. Все инструменты (базовое обновление)
- **Частота**: каждые 20-30 минут (текущее)
- **Охват**: все активные инструменты
- **Цель**: поддержание актуальности цен в кеше
- **Метод**: `performPriceUpdate()` (уже реализовано)

#### 1.2. Активные позиции в портфеле (высокий приоритет)
- **Частота**: каждые 1-2 минуты (в торговые часы)
- **Охват**: только инструменты с открытыми позициями
- **Цель**: актуальная стоимость портфеля и PnL
- **Метод**: новый `performPortfolioPricesUpdate()`
- **Условие**: только если `isTradingAvailable() === true`

#### 1.3. Инструменты с активными сигналами (средний приоритет)
- **Частота**: каждые 5-10 минут (в торговые часы)
- **Охват**: инструменты с активными сигналами (`CachedSignal` где `endDt > now`)
- **Цель**: проверка достижения `targetPrice` и `stoploss`
- **Метод**: новый `performActiveSignalsPricesUpdate()`
- **Условие**: только если `isTradingAvailable() === true`

#### 1.4. Инструменты с активными заявками (высокий приоритет)
- **Частота**: каждые 30 секунд - 1 минута (в торговые часы)
- **Охват**: инструменты с заявками в статусе `PENDING` или `APPROVED`
- **Цель**: мониторинг условий исполнения заявок
- **Метод**: новый `performTradingRequestsPricesUpdate()`
- **Условие**: только если `isTradingAvailable() === true`

### 2. Портфель (автоматический пересчет)

#### 2.1. Стоимость позиций
- **Триггер**: после каждого обновления цен активных позиций
- **Метод**: автоматический пересчет в `TradingEngine.getPortfolioValue()`
- **Обновление**: `VirtualPortfolio.totalValue` в БД

#### 2.2. PnL (прибыль/убыток)
- **Триггер**: после каждого обновления цен активных позиций
- **Метод**: пересчет на основе `averagePrice` и `currentPrice`
- **Обновление**: WebSocket broadcast для фронтенда

#### 2.3. Статус позиций
- **Триггер**: после каждого обновления цен активных позиций
- **Проверка**: сравнение текущей цены с `targetPrice` и `stoploss` из стратегии
- **Действие**: генерация рекомендаций SELL при достижении целей

### 3. Активные сигналы (мониторинг)

#### 3.1. Статус сигналов
- **Частота**: каждые 5-10 минут (вместе с обновлением цен)
- **Проверка**: сравнение `currentPrice` с `targetPrice` и `stoploss`
- **Действие**: обновление статуса сигнала (`active: false` при достижении целей)

#### 3.2. Уведомления о достижении целей
- **Триггер**: при достижении `targetPrice` или `stoploss`
- **Метод**: WebSocket + Telegram уведомления
- **Содержание**: информация о достигнутой цели и текущей цене

### 4. Торговые заявки (мониторинг исполнения)

#### 4.1. Статус исполнения
- **Частота**: каждые 30 секунд - 1 минута (вместе с обновлением цен)
- **Проверка**: сравнение `currentPrice` с условиями заявки
- **Действие**: автоматическое исполнение при достижении условий (если включено)

#### 4.2. Уведомления о готовности к исполнению
- **Триггер**: при приближении цены к цене заявки (±1%)
- **Метод**: WebSocket + Telegram уведомления
- **Содержание**: предупреждение о готовности к исполнению

### 5. Свечи (опционально, для активных инструментов)

#### 5.1. Минутки для активных позиций
- **Частота**: каждые 1-5 минут (в торговые часы)
- **Охват**: только инструменты с открытыми позициями
- **Метод**: `CacheService.updateCandlesIncremental(figi, 'MINUTE', 1)`
- **Цель**: детальный анализ для принятия решений

#### 5.2. Часы для активных сигналов
- **Частота**: каждые 15-30 минут (в торговые часы)
- **Охват**: инструменты с активными сигналами
- **Метод**: `CacheService.updateCandlesIncremental(figi, 'HOUR', 1)`
- **Цель**: среднесрочный анализ трендов

## Реализация

### Новые методы в SchedulerService

1. `performPortfolioPricesUpdate()` - обновление цен активных позиций
2. `performActiveSignalsPricesUpdate()` - обновление цен активных сигналов
3. `performTradingRequestsPricesUpdate()` - обновление цен активных заявок
4. `recalculatePortfolioValue()` - пересчет стоимости портфеля
5. `checkSignalsTargets()` - проверка достижения целей сигналов
6. `checkTradingRequestsConditions()` - проверка условий исполнения заявок

### Новые воркеры

1. `portfolioPricesUpdateWorker.js` - обновление цен портфеля
2. `activeSignalsPricesUpdateWorker.js` - обновление цен сигналов
3. `tradingRequestsPricesUpdateWorker.js` - обновление цен заявок

### Настройки (Settings)

```javascript
{
  // Обновление цен портфеля
  portfolio_prices_update_interval_minutes: 2, // каждые 2 минуты
  portfolio_prices_update_enabled: true,
  
  // Обновление цен активных сигналов
  active_signals_prices_update_interval_minutes: 5, // каждые 5 минут
  active_signals_prices_update_enabled: true,
  
  // Обновление цен активных заявок
  trading_requests_prices_update_interval_seconds: 60, // каждую минуту
  trading_requests_prices_update_enabled: true,
  
  // Автоматическое исполнение заявок
  auto_execute_requests_enabled: false, // по умолчанию выключено
  auto_execute_price_tolerance_percent: 1, // ±1% от цены заявки
}
```

## Оптимизация API запросов

### Батчинг запросов
- Группировать запросы цен для нескольких инструментов в один `getLastPrices()`
- Максимальный размер батча: 100 инструментов (лимит API)

### Кеширование
- Использовать `lastPriceTime` для проверки свежести данных
- Не обновлять цену, если она обновлена менее 30 секунд назад
- Приоритет: активные позиции > активные сигналы > активные заявки > все остальные

### Rate Limiting
- Соблюдать задержку между запросами (текущая: 1 секунда)
- В торговые часы: более частые обновления
- Вне торговых часов: только базовое обновление (каждые 20 минут)

## Мониторинг и логирование

### Метрики для отслеживания
- Количество обновленных цен по категориям
- Время выполнения обновлений
- Количество API запросов в минуту
- Количество сработавших сигналов/заявок

### Логирование
- Уровень INFO: успешные обновления
- Уровень WARN: пропущенные обновления (старые данные)
- Уровень ERROR: ошибки API или БД

## Оценка нагрузки на API

### Текущая нагрузка
- Обновление всех цен: ~1000 запросов каждые 20 минут = ~50 запросов/минуту
- Обновление торговых часов: ~2 запроса каждые 15 минут = ~0.13 запросов/минуту

### Предлагаемая нагрузка
- Базовое обновление: ~50 запросов/минуту (без изменений)
- Портфель (10 позиций): ~5 запросов/минуту (каждые 2 минуты)
- Активные сигналы (20 сигналов): ~4 запросов/минуту (каждые 5 минут)
- Активные заявки (5 заявок): ~5 запросов/минуту (каждую минуту)
- **Итого**: ~64 запросов/минуту (в пределах лимитов API)

### Вне торговых часов
- Только базовое обновление: ~50 запросов/минуту
- Остальные задачи отключены автоматически
