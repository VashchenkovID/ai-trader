# Метрики: прогноз модели и симуляция на paper

Две разные цели — **не смешивать** при отчётах и промоуте моделей.

## 1. Качество прогноза (forecast quality)

Относится к **NN / ансамблю / weekly**, до или независимо от торговли.

| Метрика | Смысл |
|--------|--------|
| **MSE / MAE** по нормализованной целевой доходности (как в `CondMLPLightning`) | Ошибка уровня score vs фактическая доходность на горизонте |
| **Direction accuracy** | Доля верно угаданного знака движения на тесте (см. `training/backtest.py`) |
| **Brier score / reliability** | Калибровка вероятностей, если выход интерпретируется как вероятность |
| **Walk-forward / OOS** | Стабильность метрик по скользящим окнам без look-ahead |

**Где смотреть:** MLflow при `training.run_nn`, артефакты бэктеста, `test_mse`, `test_direction_accuracy` в логах обучения.

## 2. Качество симуляции на виртуальном портфеле (paper PnL / policy)

Относится к **цепочке**: сигнал → заявка → исполнение paper → изменение `VirtualPortfolio`.

| Метрика | Смысл |
|--------|--------|
| **PnL / доходность счёта** | Итог по `totalValue` / начальному капиталу |
| **Sharpe / Calmar / max drawdown** | Риск-скорректированный результат на истории paper |
| **Win rate / profit factor** | По закрытым/исполненным заявкам (см. также `TrainingSettings.release_*`) |

**Где смотреть:** API портфеля, статистика заявок `EXECUTED` в режиме `paper`, JSONL `paper_mdp.jsonl` (состояние до/после сделки).

## 3. Правило отчётности

- Улучшение **прогноза** фиксируется метриками из §1 на **отложенной выборке**.
- Улучшение **торговой политики** на paper — метриками из §2 и, при необходимости, отдельным release-gate.
- Промоут модели в прод по **одной только** paper-доходности без проверки §1 даёт **смещение** (удачный режим рынка, а не обобщаемый прогноз).

## 4. Два сигнала: основной (UI / real) и мягкий для paper

В таблице `recommendations` хранится **основной** консервативный сигнал (`recommendation`, `confidence`, `score`) — то, что отдаёт API и UI. Дополнительно заполняются **`paper_recommendation`**, **`paper_confidence`**, **`paper_score`**: мягкий сигнал для симуляции и автопайплайна заявок в режиме `paper` (копия BUY/SELL или эвристика при HOLD).

**Pipeline** (`RecommendationPipelineService`, `mode=paper`): пороги по умолчанию задаются переменными **`PAPER_PIPELINE_MIN_CONFIDENCE`** и **`PAPER_PIPELINE_MIN_SCORE`** (ниже, чем жёсткие 0.5 для не-paper режима). По умолчанию **`PAPER_SOFT_USE_DB_COLUMNS=true`**: отбор идёт по колонкам `paper_*`, если `paper_recommendation` заполнен; **`PAPER_SOFT_USE_DB_COLUMNS=false`** — только основной сигнал, опционально с **`PAPER_SOFT_HOLD_TO_BUY`** (HOLD → BUY для отбора). Риск-лимиты (`RiskService`, `AutoPaperService`) по умолчанию не ослабляются — мягкость только на этапе отбора кандидатов.
